하나의 마스터. 수백 개의 하위 계정.

228개의 하위 계정이 있는 마스터 계정으로, 각각 위치를 나타냅니다. 새 지점이 네트워크에 추가되면 즉시 공유 연결과 설정을 상속받습니다. 운동 코치는 이렇게 단일 컨트롤 플레인에서 전체 프랜차이즈에 걸친 MindBody 통합을 관리합니다.

복잡성 없이 확장

각 하위 계정은 자체 소스 시스템 연결(예: 자체 MindBody 사이트)로 독립적으로 운영되지만, CRM 연결 및 자동화 코드베이스와 같은 중앙 관리 리소스를 공유합니다.

프랜차이즈가 5개의 새 위치를 추가하면 해당 위치가 계정 네트워크에 추가되어 공유 연결, 설정 및 자동화를 즉시 상속받습니다. 위치별 수동 설정이 필요 없습니다.
  계정 네트워크
연결 공유

하나의 연결. 모든 위치.

"하위 계정과 공유" 토글은 모든 위치에서 하나의 CRM 연결을 공유한다는 의미입니다. 228개의 별도 CRM 자격 증명이 필요하지 않습니다. 각 하위 계정은 자체 소스 시스템 연결(예: 자체 Mindbody 사이트)을 갖지만 CRM은 공유합니다.

중요한 곳은 공유. 필수적인 곳은 격리.

일부 연결은 공유되어야 합니다. CRM, 모니터링 도구, 알림 시스템 등. 다른 연결은 격리되어야 합니다. 각 위치의 소스 시스템 자격 증명은 해당 하위 계정에 비공개로 유지됩니다.

Admin Console은 공유 대상과 비공유 대상을 토글 수준에서 제어할 수 있습니다. 코드 없이. 구성 파일 없이. 스위치 하나로.

속도 제한

플랫폼 수준의 속도 제한. 코드 필요 없음.

Admin Console에서 "10초당 185회 API 호출"을 직접 설정합니다. 플랫폼이 228개 모든 위치에 자동으로 적용합니다. 코드 없이, 외부 속도 제한 도구 없이, 위치별 구성 없이.

한 번 구성. 모든 곳에 적용.

속도 제한은 플랫폼 수준에서 연결별로 구성됩니다. 네트워크의 모든 계정에 걸쳐 모든 자동화가 자동으로 제한을 준수합니다. API 파트너가 "10초당 185회 호출"이라고 알려주면, 해당 숫자를 한 번만 입력하면 플랫폼이 나머지를 처리합니다.

플랫폼이 요청을 대기열에 넣고, 시간 창에 걸쳐 균등하게 분배하며, 제한에 접근하면 우아하게 속도를 줄입니다. 429 오류가 고객에게 도달하지 않습니다. 자동화에 커스텀 쓰로틀링 코드가 필요하지 않습니다.

마스터 계정 라우팅

CRM에서 데이터가 오고 올바른 소스 시스템으로 돌아가야 할 때 마스터 계정이 적절한 하위 계정으로 디스패치합니다. 플랫폼이 라우팅을 자동으로 처리합니다. 수동 매핑 없이, 조회 테이블 없이, 레코드가 어떤 위치에 속하는지 추측 없이.

"연락처 업데이트가 HubSpot으로 들어옵니다. 마스터 계정은 웹훅을 수신하고 위치 필드를 기반으로 연락처가 속한 MindBody 사이트를 식별한 다음 업데이트를 올바른 하위 계정으로 라우팅합니다. 하위 계정은 자체 MindBody 자격 증명을 사용하여 자체 자동화를 통해 이를 처리합니다. 연락처는 뒤에 228개의 위치가 있다는 사실을 전혀 알지 못합니다."

배포

배포 및 업그레이드. 한 번에 모두.

연결된 모든 계정에 원클릭 배포

코드베이스 그룹을 선택하고 연결된 모든 계정에 동시에 업그레이드를 배포합니다. 수동 롤아웃이 없습니다. 버전 불일치가 없습니다. 누락된 위치가 없습니다.

버그를 수정하거나 기능을 추가하면 모든 고객이 동시에 받습니다. 배포 워크플로우는 플랫폼에 내장되어 있으며, 사후에 덧붙인 것이 아닙니다.

배포는 원자적으로 이루어집니다. 모든 계정에 업데이트가 적용되거나 적용되지 않을 수 있습니다. 클릭 한 번으로 롤백할 수 있습니다. 네트워크 전체에 적용하기 전에 일부 계정에 배포하여 단계적으로 롤아웃할 수도 있습니다.

모니터링

150번 위치에서 문제가 있다고 하면 몇 초 만에 답변합니다

대규모 연동을 지원한다는 것은 질문에 빠르게 답하는 것을 의미합니다. APIANT는 모든 자동화, 모든 데이터 흐름, 모든 API 호출에 대한 완전한 가시성을 제공합니다. 고객 ID, 이메일, 레코드 번호 등 모든 데이터를 검색하면 해당 데이터가 거쳐 간 모든 단계, 모든 변환, 모든 API 응답을 즉시 확인할 수 있습니다. 로그를 뒤질 필요가 없습니다. 추측이 필요 없습니다.

엔터프라이즈 모니터링 통합

엔터프라이즈 배포의 경우 Splunk, Datadog 또는 모니터링 도구에 연결하여 API 처리량, 오류율, 속도 제한 준수를 보여주는 실시간 대시보드를 구현할 수 있습니다.

각 연결을 통해 초당 몇 건의 API 호출이 흐르는지, 어떤 자동화가 실행 중인지, 속도 제한에 접근하고 있는 것이 있는지 정확히 확인할 수 있습니다. 운영 팀이 이미 사용 중인 모니터링 도구에서 모두 확인 가능합니다.

데이터 검색 및 검사

고객 ID, 예약 번호, 이메일 주소 등 모든 데이터를 검색하면 자동화에서 해당 데이터가 거쳐 간 모든 단계를 즉시 확인할 수 있습니다. 원시 API 요청, 적용된 변환 및 대상에 기록된 최종 결과를 확인할 수 있습니다.

프랜차이즈 위치에서 고객의 멤버십 상태가 올바르게 동기화되지 않았다고 보고하면, 고객 ID를 검색하여 몇 초 만에 전체 과정을 확인할 수 있습니다. 어떤 자동화가 처리했는지, 어떤 데이터가 들어왔는지, 분기 로직이 어떤 결정을 내렸는지, CRM에 무엇이 기록되었는지.
