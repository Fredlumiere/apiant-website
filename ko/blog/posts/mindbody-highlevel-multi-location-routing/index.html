프랜차이즈 대표 소유권을 둘러싼 갈등

여러 지점을 운영하는 부티크 짐 브랜드들은 거의 항상 똑같은 내부 갈등에 직면합니다. 잠재 고객이 본사 웹사이트 양식을 작성했습니다. 본사 마케팅팀이 클릭을 유도했습니다. 이 잠재 고객은 A 지점 근처에 살고 B 지점 근처에서 일합니다. 첫 달에 두 지점 모두 방문합니다. 그렇다면 이 잠재 고객의 소유권은 누구에게 있을까요? 누가 수수료를 받을까요? 이 고객을 유치한 광고 비용은 누가 부담할까요?

가상 사례: 트레이드윈드 애슬레틱 네트워크(예시)는 12개 지점을 보유한 프랜차이즈 브랜드로 7,200명의 회원을 두고 있습니다. 각 프랜차이즈 가맹점은 자체적인 하이레벨(HighLevel) 하위 계정을 운영하며, 본사는 브랜드 전체 마케팅을 담당합니다. 통합 과정에 명확한 라우팅 규칙이 없다면, 지점 간 회원 간의 소통은 언제든 슬랙(Slack)에서 논쟁으로 이어질 수 있습니다.

기성 도구가 프랜차이즈 규모에서 실패하는 이유

여러 위치에서 HighLevel과 Mindbody를 함께 사용하는 것은 하위 계정 문제이자 site_id 문제입니다. 대부분의 일반적인 도구는 둘 중 하나만 처리합니다.

  • 그들은 우편번호를 기준으로 경로를 지정합니다(하지만 도시 경계를 넘어서면 제대로 작동하지 않고 회원이 실제로 이용하는 체육관은 고려하지 않습니다).
  • 이러한 요청은 프랜차이즈 가맹점주가 접근할 수 없는 단일 "중앙" HighLevel 계정으로 연결됩니다.
  • 이들은 여러 상위 계정으로 라우팅되지만 중복 제거가 되지 않으므로 동일한 구성원이 두 개의 하위 계정에 연락처를 생성합니다.

맞춤형 시스템은 작동하지만, 새로운 프랜차이즈가 문을 열거나, 하위 계정이 재구성되거나, 회원이 다른 체육관으로 이동할 때마다 지속적인 유지 관리가 필요합니다. 통합이 핵심이 되어야 하며, 기업 운영 관리자가 수작업으로 관리하는 스프레드시트가 되어서는 안 됩니다.

APIANT 접근법

CRMConnect Mindbody to HighLevel에는 다음이 포함됩니다. 다중 위치 지원 이 기능은 바로 이러한 경우를 위해 설계된 최고급 기능입니다. API 앱 페이지에는 다음과 같이 설명되어 있습니다. "단일 HighLevel 계정으로 동기화된 여러 Mindbody 사이트를 효율적으로 관리하세요. 프랜차이즈 및 다지점 사업에 이상적이며, 잠재 고객을 각 Mindbody 지점으로 자동 라우팅합니다." 여러 하위 계정으로 구성된 프랜차이즈 네트워크의 경우에도 동일한 라우팅 로직이 하위 계정별로 적용됩니다.

프랜차이즈 모델을 특징짓는 요소들은 다음과 같습니다.

  • 다중 위치 지원 사이트와 하위 계정 간의 매핑을 위해.
  • 양방향 클라이언트 동기화 따라서 기업에서 확보한 잠재 고객 정보는 해당 프랜차이즈의 마인드바디 사이트로 전달됩니다.
  • 스마트 중복 프로필 처리 따라서 여러 지역에 걸쳐 있는 구성원은 연락처가 하나가 아니라 하나입니다.
  • 140개 이상의 사용자 지정 연락처 필드 따라서 홈 위치, 보조 위치 및 마지막 방문 위치는 모두 쿼리 가능한 속성으로 존재합니다.

CRMConnect에서 다중 위치 라우팅은 어떻게 작동하나요?

설정은 간단합니다.

  1. Mindbody의 각 지점은 안정적인 계정으로 CRMConnect에 등록되어 있습니다. site_id.
  2. 각 HighLevel 하위 계정은 안정적인 계정에 등록됩니다. subaccount_id.
  3. 사이트와 하위 계정 간의 매핑이 정의됩니다. site_id -> subaccount_id.
  4. (중앙 집중식 수집 양식에서 가져온) 새로운 리드에 대한 라우팅 규칙:
  5. 리드 양식에 위치 태그가 포함된 경우, 매핑된 하위 계정으로 연결하고 매핑된 Mindbody 사이트로 푸시합니다.
  6. 태그가 없으면 분류를 위해 "중앙" 보관 하위 계정으로 라우팅합니다.
  7. 기존 회원에 대한 라우팅 규칙:
  8. 회원의 mindbody_home_location 이 필드는 기본 하위 계정을 정의합니다.
  9. 여러 장소를 방문하는 경우, 해당 연락처의 홈 하위 계정에 이벤트로 기록됩니다.

스마트한 중복 방지 로직은 가장 흔한 오류, 즉 동일한 이메일 주소로 같은 주에 사이트 A와 사이트 B에서 가입하는 상황을 방지합니다. CRMConnect는 일치하는 항목을 감지하여 단일 연락처로 병합하고 프로필에 두 위치를 모두 표시합니다.

중복 없이 사이트를 하위 계정에 매핑

Routing configuration:
site-01 (Downtown) -> subaccount-tradewind-downtown
site-02 (Pearl)    -> subaccount-tradewind-pearl
site-03 (Eastside) -> subaccount-tradewind-eastside
...
site-12 (Airport)  -> subaccount-tradewind-airport

HighLevel contact custom fields:
- mindbody_home_location_id          primary site, drives sub-account ownership
- mindbody_home_location_name
- mindbody_visited_sites_30d         list of site_ids
- mindbody_last_visit_site_id        most recent visit location
- mindbody_lead_source_site_id       set at lead capture, never overwritten

그만큼 home_location_id 리드 소유권 필드입니다. 리드가 유료 회원이 되는 순간 설정되며, 문서화된 절차(회원이 도시를 옮기거나, 주 이용 체육관을 변경하는 경우)를 통해 재지정될 수 있습니다. visited_sites_30d 이 필드는 소유권 변경 없이 여러 위치에서 발생하는 활동을 포착합니다.

계정 없이 사이트 간 회원 활동 확인 (Crossfire)

본사 운영팀은 모든 하위 계정에 대한 깔끔한 개요를 확인할 수 있습니다. 각 가맹점주는 자신의 연락처만 볼 수 있습니다. 지점 간 활동은 필요한 곳에 기록됩니다.

  • 회원의 홈 하위 계정: 전체 내역, 주요 연락처 정보.
  • 방문한 (자택 이외의) 사이트 보고서는 연락처 기록이 아닌 "방문객" 항목에 표시됩니다.

사이트 B의 가맹점주가 사이트 A 회원의 잦은 방문을 발견했을 경우, 본사 운영 절차를 통해 회원 이동을 요청할 수 있습니다. 시스템은 이동을 지원하지만, 어느 가맹점주도 해당 회원의 연락처를 직접 가져갈 수는 없습니다. 이 규칙은 통합 단계에서 적용됩니다.

결과적으로 슬랙에서 논쟁할 필요가 없어졌습니다. 소유권이 한 곳에 집중되고, 여러 지점에서 발생하는 수익은 해당 지점에서 실제로 사용을 통해 얻은 수익으로 귀속되며, 먼저 광고를 노출한 지점에 귀속되지 않습니다.

7,200명 회원 기준 대표적인 운영 성과

이 이미지는 예시용 합성 이미지이며 실제 고객의 모습이 아닙니다.

  • 상위 계정 하위 계정 간 중복 연락처 수가 분기별로 감소하여, 이전에는 반복적인 정리 작업이 필요했지만 현재는 분기당 약 5~15건의 병합만 발견됩니다.
  • 프랜차이즈 관련 분쟁 해결에 소요되는 본사 운영 시간은 주당 약 6~10시간이며, 이는 회수된 시간입니다.
  • 중앙 집중식으로 수집된 잠재 고객의 첫 방문까지 걸리는 시간: 접수 시점에 바로 담당자가 배정되므로 수동 인계가 아닌 첫 방문까지 걸리는 시간이 1~2일 단축됩니다.
  • 멤버 이전 요청은 (임시방편이 아닌) 하나의 프로세스 내에서 모두 처리됩니다. 이는 통합 시스템이 단일 홈 위치를 강제하기 때문입니다.

리프트는 대부분 정치적인 문제입니다. 통합은 소유권 규칙을 협상이 아닌 시스템으로 만듦으로써 논쟁을 종식시킵니다.

건설업체 테이크아웃

  • 사이트를 하위 계정과 연결하는 매핑을 통합에 포함시키세요. 스프레드시트를 이용한 라우팅은 프랜차이즈 3개 이상으로 확장되지 않습니다.
  • 사용 home_location_id 단일 소유권 필드로서, 여러 지역을 방문하는 것은 활동이지 소유권 주장이 아닙니다.
  • 통합 기능을 통해 중복 제거를 강제합니다. 경계면에서의 스마트 매칭은 분기별 정리 작업을 줄여줍니다.
