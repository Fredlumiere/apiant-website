⚖ 특허 출원 중인 기술

 클로드 코드로 작동 가능 · 실시간 재고


프롬프트 하나. 통합 하나.
클로드 코드(Claude Code)는 플랫폼의 전반적인 개발을 주도합니다.


APIANT Claude Code 플러그인을 설치하면 Claude Code가 통합 빌드, 어셈블리 편집, 테스트 실행, 프로덕션 배포, 문서 작성 및 고객 문제 진단 기능을 수행할 수 있게 됩니다. 아래는 Claude Code가 실제로 활용할 수 있는 42가지 스킬과 138가지 MCP 도구의 전체 목록입니다.


 APIANT 클로드 코드 플러그인 버전 1.0.0 · 빌드 36



40 플러그인 기술
127 MCP 도구
3 작업 공간
1 프롬프트 → 통합 배송됨
















작동 방식


플러그인 하나로 모든 플랫폼에 접근 가능합니다.


APIANT Claude Code 플러그인은 세 개의 MCP 서버와 스킬 라이브러리를 제공합니다. 플러그인을 설치하고 Claude Code를 실행하면 전체 플랫폼에 자연어를 통해 접근할 수 있게 됩니다.













01 · 설치


apiant-설정


한 번 실행하세요. 플러그인은 MCP 연결, 환경 변수 및 플러그인 버전을 확인합니다. Claude가 현재 활성화된 항목과 누락된 항목을 알려줍니다.











02 · 프롬프트


쉬운 말로 질문해 주세요.


"Shopify와 Mindbody를 동기화하는 방법을 알아보세요." 클로드 코드(Claude Code)는 적절한 기술을 선택하고, 적합한 도구를 활성화하고, 실시간 피드백을 통해 실행을 시작합니다.











03 · 배송


구축, 테스트, 배포


클로드는 어셈블리를 구성하고, 엔드 투 엔드 테스트를 수행하고, 오류를 수정하고, 프로덕션 환경에 배포하고, 계정을 모니터링하는 모든 작업을 인수인계 없이 수행합니다.

















전체 재고 목록


10가지 워크플로우에 걸쳐 42가지 스킬을 습득할 수 있습니다.


모든 기술은 APIANT의 선임 엔지니어가 따르는 절차이며, 클로드 코드(Claude Code)에 의해 인코딩되고 실행 가능합니다. 각 카드를 클릭하면 전체 내용/시기/방법을 확인할 수 있습니다.











설정


다른 작업을 실행하기 전에 플러그인, MCP 연결 및 환경을 확인하십시오.




1 기능










/apiant-setup


플러그인을 설정하세요


`apiant-cli` Node CLI를 사용하여 APIANT Claude Code 플러그인을 설치하거나 복구하는 과정을 사용자에게 안내합니다. 사용자가 "설정", "설치", "재설치", "플러그인 업데이트"를 요청할 때 또는 처음 실행할 때 사용하십시오.













빌드


자연어 프롬프트를 사용하여 새로운 자동화, 어셈블리, 통합 및 양식을 생성합니다.




4 기술










/build-automation


새로운 자동화 시스템을 구축하세요


MCP 도구를 사용하여 새로운 APIANT 자동화를 구축합니다. 사용자가 "자동화 구축", "자동화 생성", "X를 Y에 연결"과 같은 표현을 사용하거나 새로운 워크플로를 설명할 때 사용합니다.








/build-assembly


앱 어셈블리를 빌드합니다.


MCP 도구를 사용하여 APIANT 앱 어셈블리(API 통합 기반)를 구축합니다. 사용자가 "어셈블리 구축", "커넥터 생성", "API 액션 추가"와 같은 표현을 사용하거나 API 통합 작업에 대해 설명할 때 사용합니다.








/build-integration


통합 제품군을 구축하세요


APIANT에서 여러 자동화 기능을 통합하는 스위트를 구축하세요. 사용자가 "통합 구축", "양방향 동기화 생성", "데이터 파이프라인 구축" 또는 여러 자동화 기능을 연동해야 하는 요청을 할 때 사용하세요.








/build-form


양식을 디자인하세요


APIANT 자동화를 위한 폼을 디자인합니다. 사용자가 "폼 만들기", "폼 디자인하기", "폼 생성하기"라고 말하거나 필요한 폼을 설명할 때 사용합니다.













편집


실행 중인 자동화 및 어셈블리를 안전하게 수정하세요. 단계를 추가하고, 앱을 교체하고, 엔드포인트를 변경하고, 설정을 이름 변경할 수 있습니다.




2 기술










/edit-automation


자동화 편집


MCP 도구를 사용하여 기존 APIANT 자동화를 편집합니다. 사용자가 "자동화 편집", "단계 추가", "매핑 수정", "X를 Y로 바꾸기", "단계 이동", "단계 비활성화"와 같은 표현을 사용하거나 기존 자동화 변경 사항을 설명할 때 사용합니다.








/edit-assembly


어셈블리를 편집합니다


MCP 도구를 사용하여 기존 APIANT 어셈블리를 편집합니다. 사용자가 "어셈블리 편집", "JSP 수정", "API 호출 업데이트", "엔드포인트 변경", "설정 이름 변경", "드롭다운 편집"과 같은 표현을 사용하거나 기존 어셈블리의 코드 또는 설정 변경을 설명할 때 사용합니다.













테스트 및 배포


엔드투엔드 검증, 브랜치 커버리지, 오류 진단 및 개발 환경에서 운영 환경으로의 배포.




3 기술










/test-automation


자동화를 테스트하세요


APIANT 자동화를 처음부터 끝까지 테스트하고 검증합니다. 자동화를 실행하고, 결과를 검사하고, 오류를 진단하고, 수정 사항을 적용하고, 재테스트하고, 브랜치 커버리지를 실행합니다. 사용자가 "이 자동화를 테스트해 줘", "테스트를 실행해 줘", "자동화 X가 실패하는 이유는 뭐야?", "자동화 X의 오류를 진단해 줘"라고 말할 때 사용합니다.








/test-integration


전체 제품군을 테스트하세요


APIANT에서 다중 자동화 스위트에 대한 통합 테스트를 수행합니다. 자동화 간 데이터 흐름, 공유 상태 일관성, 루프 방지 및 자동화 간 조정을 검증합니다. 통합 스위트 구축 후 또는 사용자가 "통합을 처음부터 끝까지 테스트"하도록 요청할 때 사용합니다.








/deploy-automation


개발 환경을 프로덕션 환경에 배포


개발 환경에서 운영 환경으로 템플릿 자동화를 게시하고 고객 계정에 배포합니다(연결 또는 연결 해제, 배포 시 사용자 선택). 사용자가 "게시", "배포", "운영 환경으로 푸시" 또는 "고객 업데이트"를 요청할 때 사용합니다.













조립 트리거


APIANT는 폴링, 웹훅(세 가지 유형), 프로토콜 스레드 등 모든 방식으로 실행을 시작할 수 있습니다.




6 기술










assembly-trigger-new


NEW_ITEM 폴링 트리거


NEW_ITEM 폴링 트리거 어셈블리를 빌드하기 위한 유형별 지침입니다. 유형 분류 후 /build-assembly 명령을 통해 실행됩니다.








assembly-trigger-updated


새로운 또는 업데이트된 여론조사


NEW_OR_UPDATED 폴링 트리거 어셈블리를 빌드하기 위한 유형별 지침입니다. 유형 분류 후 /build-assembly 명령을 통해 실행됩니다.








assembly-trigger-manual-webhook


수동 웹훅


웹훅(수동 등록) 트리거 어셈블리를 구축하기 위한 유형별 지침입니다. 유형 분류 후 /build-assembly 명령어를 통해 호출됩니다.








assembly-trigger-self-registering-webhook


자체 등록 웹훅


WEBHOOK_SELF_REGISTERING 트리거 어셈블리와 해당 웹훅 삭제 액션을 빌드하기 위한 유형별 지침입니다. 유형 분류 후 /build-assembly 명령을 통해 호출됩니다.








assembly-trigger-service-webhook


서비스 웹훅


SERVICE_WEBHOOK 트리거 어셈블리(이벤트 필터링 기능이 있는 자격 증명 기반 웹훅 URL)를 구축하기 위한 유형별 지침입니다. 유형 분류 후 /build-assembly 명령을 통해 실행됩니다.








assembly-trigger-protocol-thread


프로토콜 스레드


프로토콜 스레드 트리거(PROTOCOL_THREAD_RECEIVER 및 PROTOCOL_THREAD)를 빌드하기 위한 유형별 지침입니다. 유형 분류 후 /build-assembly 명령으로 호출됩니다.













의회 활동


CRUD 기본 요소: 모든 API는 적어도 이 중 하나를 지원합니다. 모든 통합의 기본 요소입니다.

커넥터


모든 어셈블리가 기반으로 하는 인증 계층과 등록 및 마이그레이션 도구입니다.




3 기술










assembly-connector


커넥터 어셈블리


앱 커넥터 어셈블리 빌드를 위한 유형별 지침(OAuth V2, API 키 또는 자격 증명 없음). 2단계에서 /build-assembly 명령을 통해 호출됩니다.








/register-oauth-app


OAuth 앱을 등록하세요


브라우저를 통해 클라이언트 ID와 클라이언트 시크릿을 캡처하여 APIANT 키볼트에 저장함으로써 벤더의 개발자 포털에 OAuth 앱을 등록합니다. 사용자가 "OAuth 앱 등록", "OAuth 자격 증명 가져오기", "OAuth 가입"과 같은 요청을 하거나 Salesforce, HubSpot, Google 등의 벤더로부터 클라이언트 ID/시크릿을 자동으로 가져오도록 요청할 때 사용합니다.








/convert-assembly


인간을 AI로 변환하는 템플릿


사람이 직접 빌드한 APIANT 어셈블리를 AI 템플릿 패턴으로 변환합니다. asm_load 함수가 is_human_built=true를 반환하거나 사용자가 '어셈블리 변환', '어셈블리 마이그레이션', 'AI 템플릿으로 변환'을 요청할 때 사용합니다.

두 시스템이 서로 충돌하지 않고 동기화 상태를 유지하도록 하는 쌍을 이루는 트리거와 액션.




1 기능










assembly-bidirectional-sync


양방향 동기화


양방향 동기화 트리거 및 액션 어셈블리를 구축하기 위한 유형별 지침입니다. 유형 분류 후 /build-assembly 명령어를 통해 호출됩니다.













패턴


일반적인 자동화 형태에 재사용 가능한 흐름 템플릿입니다. 빌드 자동화 실행 중에 필요에 따라 불러올 수 있습니다.




10 기술










pattern-chat-widget


채팅 위젯


단순한 AI 챗봇부터 도구 자동화를 활용한 다중 목표 대화 흐름까지, 채팅 위젯 자동화를 위한 패턴 참조입니다. 이 패턴은 빌드 의도가 채팅 위젯, 챗봇, 채팅 목표, 대화 메모리, 도구를 사용하는 AI 에이전트 또는 다중 턴 채팅과 관련될 때 `/build-automation` 명령으로 로드됩니다.








pattern-csv-mapping


CSV 필드 매핑


CSV 파일이나 스프레드시트에서 필드 매핑을 가져오기 위한 패턴 참조입니다. 사용자가 시스템 간 필드 매핑 방식을 정의하는 CSV 파일을 제공하면 /build-automation에서 로드됩니다.








pattern-execute-automation


자동화 체인 실행


자동화 실행 체이닝, 부모/자식 자동화, 쿼리 문자열 매개변수 전달, 웹훅 페이로드 전달을 위한 패턴 참조입니다. 자동화 실행, 호출 또는 체이닝과 관련된 의도가 있을 때 /build-automation에서 로드됩니다.








pattern-human-moderation


인간의 중재


사람의 승인을 거치는 자동화 작업에 대한 패턴 참조입니다. 사람이 검토 대기열 링크를 통해 항목을 승인하거나 거부할 때까지 자동화 작업을 일시 중지합니다. 이 패턴은 사람의 승인, 검토, 중재, 의사 결정 게이트 또는 승인/거부 워크플로와 관련된 경우 `/build-automation` 명령어를 통해 로드됩니다.








pattern-latches


팬아웃/팬인 래치


팬아웃/팬인 자동화 래치에 대한 패턴 참조입니다. N개의 하위 자동화를 병렬로 실행하고 모두 완료될 때까지 기다립니다. 병렬 실행, 팬아웃, 팬인 또는 래치 그룹과 관련된 의도일 때 /build-automation에서 로드됩니다.








pattern-snooze


선잠


미래의 특정 날짜/시간까지 자동화를 일시 중지/재정지하는 데 사용되는 패턴 참조입니다. 자동화 실행을 일시 중지, 지연, 일시 정지, 대기 또는 특정 시간까지 기다리는 등의 의도가 있을 때 `/build-automation` 명령으로 로드됩니다.








pattern-collector


수집기


Collector 자동화를 위한 패턴 참조입니다. 여러 실행에 걸쳐 항목을 명명된 버킷에 집계한 다음, 예약된 일정이나 트리거에 따라 버킷을 비웁니다. 이 패턴은 "집계", "시간 경과에 따른 수집", "일일 요약", "일괄 처리", "버킷" 또는 "오늘 항목 요약 이메일 전송"과 같은 의도가 포함될 때 /build-automation에서 로드됩니다.








pattern-mcp-tool


MCP 도구


MCP 도구 자동화, 즉 MCP 클라이언트(Claude Desktop, Cursor, ChatGPT MCP 등)에서 호출 가능한 도구로 노출되는 자동화에 대한 패턴 참조입니다. "Claude에 노출", "MCP 클라이언트에 노출", "MCP 도구", "모델 컨텍스트 프로토콜" 또는 "AI 비서에서 호출 가능하게 만들기"와 같은 의도가 있을 때 /build-automation 명령으로 로드됩니다.








pattern-system-utilities


시스템 유틸리티


이 도구 모음은 간단한 시스템 유틸리티 레시피를 제공합니다. 피드(RSS/Atom/RDF), PDF 생성, 데이터 파일(일일 CSV) 생성 등 한 번의 작업으로 모든 기능을 실행할 수 있습니다. `/build-automation` 명령어를 사용하여 `RSS`, `Atom`, `feed`, `publish a feed`, `monitor a news source`, `generate a PDF`, `PDF attachment`, `log to CSV`, `datafile`, `daily CSV export`, 또는 `feed data into ChatGPT`와 같은 의도를 입력했을 때 로드됩니다.








pattern-web-service


웹 서비스


웹 서비스 자동화, 호출자가 응답을 기다리는 동기식 HTTP 엔드포인트에 대한 패턴 참조입니다. 이 패턴은 "HTTP 엔드포인트로 노출", "REST API", "응답이 있는 동기식 웹훅", "다른 시스템에서 호출 가능", 또는 "호출자에게 데이터를 반환하는 자동화"와 같은 의도가 있을 때 /build-automation에서 로드됩니다.

/support


고객 문제 진단


고객 자동화 문제를 진단하고, 오작동하는 실행을 중지하고, 장애 발생 시 계정 그룹을 일괄 비활성화(추후 복원 가능)하고, 새 고객 계정을 프로비저닝합니다. 실행 기록을 검색하고, 오류를 추적하고, HTTP 요청을 추출하고, 폭주하는 자동화를 중지하고, 스냅샷을 생성하고, 상위 계정과 연결된 하위 계정에서 현재 실행 중인 모든 자동화를 비활성화한 다음 장애 발생 후 복원합니다. admin_create_account를 통해 통합 제품에 대한 새 APIANT 계정을 생성합니다. 지원 담당자가 "X가 처리되지 않은 이유", "고객 Y를 확인해 보세요", "무엇이 문제인가요?", "이 자동화를 중지해 주세요", "X에 대한 모든 자동화를 꺼 주세요", "킬 스위치", "상위 및 하위 계정 모두에서 비활성화", "GHL 장애", "API가 큐를 과부하 상태로 만들고 있습니다", "장애 발생 후 자동화를 복원해 주세요", "X 장애 이후 여전히 비활성화된 항목은 무엇인가요?", "[제품]에 대한 새 계정을 생성해 주세요", "계정을 프로비저닝해 주세요", "[통합]에 대한 계정을 생성해 주세요"와 같은 질문을 할 때 사용합니다.

/report-mcp-issue


MCP 버그를 신고하세요


MCP 서버 자체에서 잘못된 동작이나 오류가 발생하는 경우, 잘못된 응답 형태, 문서와 동작 간의 불일치, 처리되지 않은 오류, 스키마 위반, 응답에 필수 필드 누락, 이전에 정상적으로 작동했던 입력에 대한 회귀 오류, 또는 문서화된 동작이 실제로는 작동하지 않는 경우 APIANT의 내부 문제 해결팀에 버그 보고서를 제출하십시오. 자신의 도구 오용, 잘못된 사용자 입력 또는 플랫폼이 설계대로 작동하는 경우에는 보고하지 마십시오. 문제가 발생하면 즉시 보고서를 제출하십시오. 사용자에게 먼저 허락을 구할 필요는 없습니다. "도구가 잘못된 형태를 반환했습니다", "스키마 위반", "작동해야 하는데 작동하지 않습니다", "계약 불일치", "MCP에서 처리되지 않은 오류가 반환되었습니다", "도구 설명에는 X라고 되어 있지만 실제로는 Y입니다", "응답에 필수 필드가 누락되었습니다", "이전에는 작동했습니다", "문서화된 동작이 작동하지 않습니다", "[도구]에서 회귀 오류가 발생했습니다"와 같은 상황이 발생하거나, MCP 계층의 버그를 보고하는 대신 조용히 해결하려는 유혹이 들 때 이 기능을 사용하십시오.

















MCP 도구


138개의 도구. 10가지 도구 세트. 필요에 따라 활성화 가능.


스킬이 워크플로우를 주도합니다. MCP 도구는 APIANT의 개발, 운영 및 문서 환경에서 실제 작업을 수행합니다. 도구는 툴셋으로 그룹화됩니다. 핵심 툴셋만 항상 로드되고, 나머지는 스킬에서 요청할 때 활성화되므로 에이전트의 컨텍스트는 간결하게 유지되고 기능은 심층적으로 활용됩니다.





개발 환경과 생산 환경은 동일한 132개 툴 표면을 공유합니다. Prod는 기본적으로 읽기 전용이며, 명시적인 확인이 있을 때만 쓰기 게이트가 활성화됩니다. 아무 카드나 토글하여 prod 버전을 확인하세요.

클로드 코드가 세션을 시작할 때 방향을 잡고, 기술을 선택하고, 필요에 따라 더 많은 도구를 활성화하는 데 필요한 설정입니다.

왜 웹훅이 아닌 폴링을 사용하는가?


Mindbody 웹훅은 이벤트 발생량이 많은 기간 동안 이벤트를 조용히 삭제합니다. Claude는 기본적으로 5분 간격으로 폴링하도록 설정했으며, 향후 Mindbody 통합 시 동일한 처리가 적용되도록 패턴 라이브러리에 이를 알려진 문제점으로 기록했습니다.

왜 어셈블리 레이어에서 스로틀링을 하는가?


자동화별로 스로틀링을 적용하면 다른 HubSpot 플로우에서도 예산이 소진될 수 있습니다. 어셈블리(커넥터 + 액션) 수준에서 스로틀링을 적용하면 테넌트 내 모든 자동화에 제한이 적용되므로 공유 API에 적합한 수준입니다.
