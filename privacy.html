3. MCP SERVER INFRASTRUCTURE

In Short: APIANT provides MCP (Model Context Protocol) server infrastructure that our customers deploy on their own dedicated servers and domains. When your data is processed through a customer's APIANT-powered MCP server, we process only the data necessary to execute the requested actions. We do not use MCP interaction data to train AI models, serve advertising, or build user profiles.

How APIANT MCP servers work

APIANT enables its customers ("builders") to deploy MCP-compatible servers on their own dedicated infrastructure and domains. These MCP servers allow the builder's end users to interact with the builder's integrations and automations through AI platforms (such as Claude by Anthropic) using natural language. When an end user connects to a builder's MCP server, the AI platform sends tool call requests to the builder's APIANT-powered server. APIANT provides the underlying platform infrastructure; end users connect to the builder's server, not to APIANT directly.

What data is processed through MCP servers

When data is processed through an APIANT-powered MCP server, the following categories of data may be involved:

  • Authentication credentials: OAuth 2.0 tokens or other credentials used to verify identity and authorize access to the builder's server.
  • Tool call parameters: The specific inputs required to execute each requested action (for example, application names, workflow configurations, or search queries).
  • Tool call responses: The results returned by the builder's server in response to requests, which are relayed back to the AI platform for display to the end user.

APIANT does not receive the full text of conversations between end users and AI platforms. Only the structured tool call data necessary to execute specific actions is processed on the builder's APIANT-powered server.

How we use MCP data

APIANT, as the platform infrastructure provider, uses data processed through MCP servers solely to:

  • Provide and operate the Platform infrastructure on behalf of the builder
  • Monitor server performance, uptime, and error rates
  • Debug issues and improve the reliability of the MCP server infrastructure
  • Comply with applicable legal obligations

How we store and retain MCP data

  • Authentication tokens are held in memory for the duration of the session and are not persisted after disconnection.
  • Tool call logs (parameters and responses) may be retained for a limited period for debugging and operational purposes. These logs are purged within 90 days unless a longer retention period is required by law.
  • No user profiles are built from MCP interaction data.

What we do NOT do with MCP data

  • We do not use MCP interaction data to train any AI or machine learning models.
  • We do not sell MCP interaction data to third parties.
  • We do not use MCP interaction data for advertising, profiling, or marketing purposes.
  • We do not share MCP interaction data with third parties except as necessary to provide the Services or as required by law.

Your rights regarding MCP data

If you are an end user of a builder's APIANT-powered MCP server, please contact the builder directly regarding your data rights. If you are an APIANT customer (builder), you may request access to, correction of, or deletion of any personal data processed through your MCP server infrastructure by contacting us at privacy@apiant.com. See "WHAT ARE YOUR PRIVACY RIGHTS?" below for additional details.

11. CONTROLS FOR DO-NOT-TRACK FEATURES

Most web browsers and some mobile operating systems and mobile applications include a Do-Not-Track ("DNT") feature or setting you can activate to signal your privacy preference not to have data about your online browsing activities monitored and collected. At this stage, no uniform technology standard for recognizing and implementing DNT signals has been finalized. As such, we do not currently respond to DNT browser signals or any other mechanism that automatically communicates your choice not to be tracked online. If a standard for online tracking is adopted that we must follow in the future, we will inform you about that practice in a revised version of this Privacy Notice.

California law requires us to let you know how we respond to web browser DNT signals. Because there currently is not an industry or legal standard for recognizing or honoring DNT signals, we do not respond to them at this time.
