⚖ TECNOLOGÍA CON PATENTE EN TRÁMITE

 Operable por Claude Code · Inventario en vivo


Una indicación. Una integración.
Claude Code gestiona la plataforma de principio a fin.


Instala el plugin APIANT Claude Code y Claude Code podrá crear integraciones, editar ensamblados, ejecutar pruebas, implementar en producción, escribir documentación y diagnosticar problemas de los clientes. A continuación, se muestra el inventario completo: 42 habilidades, 138 herramientas MCP, cada una una capacidad real que Claude puede utilizar en tu nombre.

Cómo funciona


Un solo plugin. Acceso completo a la plataforma.


El plugin APIANT Claude Code incluye tres servidores MCP y una biblioteca de habilidades. Instálalo, abre Claude Code y toda la plataforma se vuelve accesible mediante lenguaje natural.













01 · INSTALAR


configuración de apiant


Ejecutar una vez. El complemento verifica las conexiones MCP, las variables de entorno y la versión del complemento. Claude anuncia qué está activo y qué falta.











02 · INDICAR


Pregunta en inglés sencillo


"Crea una sincronización entre Mindbody y Shopify". Claude Code selecciona la habilidad adecuada, activa el conjunto de herramientas correcto y comienza a ejecutar con retroalimentación en tiempo real.











03 · ENVÍO


Construido, probado, desplegado


Claude compone los ensamblajes, realiza pruebas de extremo a extremo, corrige los fallos, implementa en producción y supervisa la cuenta, sin necesidad de traspasos.

















El inventario completo


42 habilidades en 10 flujos de trabajo.


Cada habilidad es un procedimiento que sigue un ingeniero sénior de APIANT, codificado y ejecutable por Claude Code. Haz clic en cualquier tarjeta para ver la información completa sobre qué, cuándo y cómo.

Patrones


Plantillas de flujo reutilizables para formas de automatización comunes. Se cargan bajo demanda durante /build-automation.




10 habilidades










pattern-chat-widget


Widget de chat


Referencia de patrones para automatizaciones de widgets de chat, desde chatbots de IA sencillos hasta flujos de conversación con múltiples objetivos y automatizaciones de herramientas. Cargado por /build-automation cuando la intención involucra widget de chat, chatbot, objetivo de chat, memoria de conversación, agente de IA con herramientas o chat de varias rondas.








pattern-csv-mapping


Mapeo de campos CSV


Referencia de patrón para importar asignaciones de campos desde un archivo CSV o una hoja de cálculo. Se carga mediante /build-automation cuando el usuario proporciona un archivo CSV que define cómo deben asignarse los campos entre sistemas.








pattern-execute-automation


Ejecutar encadenamiento de automatización


Referencia de patrones para encadenamiento de automatizaciones de ejecución, automatizaciones padre/hijo, paso de parámetros de cadena de consulta y reenvío de carga útil de webhook. Cargado por /build-automation cuando la intención implica ejecutar, llamar o encadenar automatizaciones.








pattern-human-moderation


Moderación humana


Patrón de referencia para la moderación humana: pausa una automatización hasta que una persona apruebe o rechace un elemento mediante un enlace a la cola de moderación. Se carga mediante /build-automation cuando la intención implica aprobación, revisión, moderación, puntos de decisión o flujos de trabajo de aprobación/rechazo por parte de un humano.








pattern-latches


Pestillos de apertura y cierre


Patrón de referencia para bloqueos de automatización de distribución/concentración, que ejecuta N automatizaciones secundarias en paralelo y espera a que todas finalicen. Cargado por /build-automation cuando la intención implica ejecución paralela, distribución, concentración o grupos de bloqueo.








pattern-snooze


Siesta


Patrón de referencia para posponer/pausar automatizaciones hasta una fecha y hora futuras. Cargado por /build-automation cuando la intención implica posponer, retrasar, pausar, dormir o esperar hasta una hora específica.








pattern-collector


Coleccionista


Patrón de referencia para automatizaciones de Collector: agrega elementos en contenedores con nombre a lo largo de las ejecuciones y luego vacía el contenedor según una programación o un activador. Cargado por /build-automation cuando la intención incluye "agregar", "recopilar a lo largo del tiempo", "resumen diario", "lote", "contenedor" o "enviar un correo electrónico de resumen de los elementos de hoy".








pattern-mcp-tool


Herramienta MCP


Referencia de patrones para automatizaciones de herramientas MCP, automatizaciones expuestas a clientes MCP (Claude Desktop, Cursor, ChatGPT MCP, etc.) como herramientas invocables. Cargado por /build-automation cuando la intención implica "exponer a Claude", "exponer a cliente MCP", "herramienta MCP", "Protocolo de contexto de modelo" o "hacer que esto sea invocable desde un asistente de IA".








pattern-system-utilities


Utilidades del sistema


Libro de recetas de pequeñas utilidades del sistema, Feed (RSS/Atom/RDF), generación de PDF, Datafile (CSV diario) y otras utilidades de una sola acción. Cargado por /build-automation cuando la intención coincide con "RSS", "Atom", "feed", "publish a feed", "monitor a news source", "generate a PDF", "PDF attachment", "log to CSV", "datafile", "daily CSV export" o "feed data into ChatGPT".








pattern-web-service


Servicio web


Referencia de patrones para automatizaciones de servicios web, puntos finales HTTP síncronos donde el solicitante espera una respuesta. Cargado por /build-automation cuando la intención implica "exponer como un punto final HTTP", "API REST", "webhook síncrono con respuesta", "invocable desde otro sistema" o "automatización que devuelve datos al solicitante".













Operaciones y soporte


Mantenga la producción en buen estado: supervise las cuentas, diagnostique fallos y ajuste el comportamiento de las alertas.




5 habilidades










/monitor-account


Supervisar la cuenta de un cliente


Supervisa las automatizaciones de una cuenta de cliente para detectar errores de ejecución en producción. Úsalas cuando el usuario diga "supervisar cuenta", "comprobar errores", "vigilar esta cuenta" o después de implementar automatizaciones para un cliente. Diseñadas para uso recurrente mediante /loop.








/support


Diagnosticar un problema del cliente


Diagnostique problemas de automatización de clientes, detenga ejecuciones con comportamiento anómalo, desactive masivamente un grupo de cuentas como interruptor de emergencia (con restauración posterior) y aprovisione nuevas cuentas de clientes. Busca en el historial de ejecución, rastrea fallos, extrae solicitudes HTTP, detiene automatizaciones descontroladas, crea instantáneas y desactiva todas las automatizaciones actualmente activas en una cuenta principal y sus cuentas secundarias vinculadas, y luego las restaura después del incidente. Crea nuevas cuentas APIANT para productos de integración a través de admin_create_account. Úselo cuando el soporte diga "¿por qué X no procesó?", "verifique al cliente Y", "¿qué está roto?", "detenga esta automatización", "desactive todas las automatizaciones para X", "interruptor de emergencia", "desactive en la cuenta principal y secundaria", "interrupción de GHL", "la API está saturando la cola", "restaure las automatizaciones después del incidente", "¿qué sigue desactivado del incidente X?", "cree una nueva cuenta para [producto]", "aprovisione una cuenta", "inicie una cuenta para [integración]".








/alert-handling


Ajustar el comportamiento de las alertas


Inspeccione, ajuste o depure cómo APIANT maneja los errores de automatización, la elegibilidad para reintentos, el apagado automático 401, las transformaciones de mensajes de alerta y la lista de descarte. Úselo cuando el usuario diga "mapeo de alerta", "suprimir alerta", "regla de alerta", "alertas ruidosas", "¿por qué mi mensaje de error decía...", "mi alerta no se activa", "¿por qué mi automatización no se reintentó?", "la automatización se desactivó con 401", "agregar a errores reintentables", "ignorar 401 para este dominio" o pregunte por qué se reescribió un correo electrónico de error.








/docs


Responder preguntas sobre cómo hacerlo


Responda preguntas sobre APIANT basándose en la documentación pública en info.apiant.com, explicando cómo funcionan las cosas, cómo hacer algo, qué es una función y dónde encontrar una configuración. Úselo cuando el usuario pregunte "¿cómo hago esto?", "¿qué es?", "¿dónde está?", "¿me lo explican?", "¿qué hace X?" o cualquier pregunta sobre la plataforma que no sea una solicitud de compilación, prueba o diagnóstico.








/report-mcp-issue


Informar de un error de MCP


Envíe un informe de error al triaje interno de APIANT cuando observe que el propio servidor MCP devuelve un comportamiento incorrecto o roto, una forma de respuesta incorrecta, una desviación del contrato entre la documentación y el comportamiento, errores no controlados, violaciones del esquema, campos obligatorios faltantes en la respuesta, regresión en entradas que antes funcionaban o un comportamiento documentado que en realidad no funciona. NO para el mal uso de su propia herramienta, entradas de usuario incorrectas o comportamiento de la plataforma que está funcionando según lo previsto. Autónomo, envíe el informe inmediatamente cuando lo vea, no pida permiso al usuario primero. Úselo cuando vea "la herramienta devolvió una forma incorrecta", "violación del esquema", "esto debería funcionar pero no lo hace", "desviación del contrato", "MCP devolvió un error no controlado", "la descripción de la herramienta dice X pero hace Y", "a la respuesta le falta un campo obligatorio", "esto solía funcionar", "el comportamiento documentado está roto", "regresión en [herramienta]", o en cualquier momento en que tenga la tentación de solucionar silenciosamente un error de la capa MCP en lugar de informarlo.

















Herramientas MCP


138 herramientas. 10 conjuntos de herramientas. Activación bajo demanda.


Las habilidades impulsan el flujo de trabajo. Las herramientas MCP realizan el trabajo real en los entornos de desarrollo, producción y documentación de APIANT. Las herramientas se agrupan en conjuntos. Solo el conjunto principal está siempre cargado; el resto se activa cuando una habilidad lo requiere, de modo que el contexto del agente se mantiene optimizado y la capacidad se mantiene amplia.





Los entornos de desarrollo y producción comparten la misma interfaz de 132 herramientas. Prod es de solo lectura por defecto; escribe en la puerta tras una confirmación explícita. Cambia cualquier tarjeta para ver la variante prod.

¿Por qué? · Sondeos, no webhooks


Los webhooks de Mindbody descartan eventos silenciosamente durante períodos de alto volumen. Claude optó por realizar sondeos con un cursor cada 5 minutos y señaló esto como un problema conocido en la biblioteca de patrones para que las futuras integraciones de Mindbody reciban el mismo tratamiento.











03:20 · Harden




T+03:24


/editar-ensamblajeSe ha insertado un limitador de velocidad en la acción de HubSpot.


HubSpot limita las solicitudes a 100 cada 10 segundos por aplicación. Claude inserta un limitador de ventana deslizante a nivel de ensamblaje, no de automatización, por lo que toda automatización que interactúa con HubSpot lo hereda.


llamadas a herramientas

asm_set_action_throttle({ assembly: 'hubspot.contact.update', rate: 100, window: '10s' })
asm_set_connector_throttle({ connector: 'hubspot.v3', burst: 20 })






¿Por qué limitar el flujo en la capa de ensamblaje?


La limitación por automatización permitiría que cualquier otro flujo de HubSpot agotara el presupuesto. La limitación a nivel de ensamblaje (conector + acción) aplica el límite a todas las automatizaciones del inquilino, que es el único nivel correcto para una API compartida.
