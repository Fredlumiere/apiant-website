⚖ পেটেন্ট প্রক্রিয়াধীন প্রযুক্তি

 ক্লড কোড দ্বারা পরিচালিত · লাইভ ইনভেন্টরি


একটি নির্দেশ। একটি সমন্বয়।
ক্লড কোড প্ল্যাটফর্মটি শুরু থেকে শেষ পর্যন্ত পরিচালনা করে।


APIANT Claude Code প্লাগইনটি ইনস্টল করলে, Claude Code ইন্টিগ্রেশন তৈরি করা, অ্যাসেম্বলি সম্পাদনা করা, টেস্ট চালানো, প্রোডাকশনে ডেপ্লয় করা, ডকুমেন্টেশন লেখা এবং গ্রাহকের সমস্যা নির্ণয় করার ক্ষমতা অর্জন করে। নিচে সম্পূর্ণ তালিকাটি দেওয়া হলো: ৪২টি স্কিল, ১৩৮টি MCP টুল, যার প্রতিটিই একটি বাস্তব সক্ষমতা যা Claude আপনার হয়ে ব্যবহার করতে পারে।

এটি কীভাবে কাজ করে


একটি প্লাগইন। সম্পূর্ণ প্ল্যাটফর্ম ব্যবহারের সুযোগ।


APIANT Claude Code প্লাগইনটিতে তিনটি MCP সার্ভার এবং একটি স্কিলস লাইব্রেরি অন্তর্ভুক্ত রয়েছে। এটি ইনস্টল করে Claude Code খুললে, সম্পূর্ণ প্ল্যাটফর্মটি স্বাভাবিক ভাষায় ব্যবহারযোগ্য হয়ে ওঠে।













০১ · ইনস্টল করুন


অ্যাপিয়েন্ট-সেটআপ


একবার চালান। প্লাগইনটি MCP সংযোগ, এনভায়রনমেন্ট ভেরিয়েবল এবং প্লাগইন সংস্করণ যাচাই করে। কী চালু আছে এবং কী অনুপস্থিত, তা ক্লদ ঘোষণা করেন।











০২ · প্রম্পট


সহজ ইংরেজিতে জিজ্ঞাসা করুন


মাইন্ডবডি ও শপিফাই-এর মধ্যে একটি সিঙ্ক তৈরি করুন। ক্লদ কোড সঠিক দক্ষতা বেছে নেন, সঠিক টুলসেট সক্রিয় করেন এবং লাইভ ফিডব্যাকের মাধ্যমে কাজ শুরু করেন।











০৩ · জাহাজ


নির্মিত, পরীক্ষিত, মোতায়েন করা হয়েছে


ক্লদ কোনো হস্তান্তর ছাড়াই অ্যাসেম্বলি তৈরি করেন, শুরু থেকে শেষ পর্যন্ত পরীক্ষা করেন, ত্রুটি সংশোধন করেন, প্রোডাকশনে ডেপ্লয় করেন এবং অ্যাকাউন্ট পর্যবেক্ষণ করেন।

















সম্পূর্ণ তালিকা


১০টি কর্মপ্রবাহ জুড়ে ৪২টি দক্ষতা।


প্রতিটি দক্ষতা হলো একটি কার্যপ্রণালী যা একজন সিনিয়র এপিআইএএনটি ইঞ্জিনিয়ার অনুসরণ করেন, যা ক্লড কোড দ্বারা এনকোড এবং কার্যকরযোগ্য। এর সম্পূর্ণ বিবরণ—কী/কখন/কীভাবে—জানতে যেকোনো কার্ডে ক্লিক করুন।











সেটআপ


অন্য কিছু চালানোর আগে প্লাগইন, এর এমসিপি সংযোগ এবং পরিবেশ যাচাই করুন।




1 দক্ষতা










/apiant-setup


প্লাগইনটি সেট আপ করুন


`apiant-cli` নোড সিএলআই ব্যবহার করে ব্যবহারকারীকে APIANT Claude Code প্লাগইনটি ইনস্টল বা মেরামত করার প্রক্রিয়াটি ধাপে ধাপে বুঝিয়ে দিন। ব্যবহারকারী যখন "setup", "install", "reinstall", "update plugin" বলবে, অথবা প্রথমবার চালানোর সময় এটি ব্যবহার করুন।













নির্মাণ করুন


স্বাভাবিক ভাষার নির্দেশনা থেকে নতুন অটোমেশন, অ্যাসেম্বলি, ইন্টিগ্রেশন এবং ফর্ম তৈরি করুন।

একটি নতুন অটোমেশন তৈরি করুন

/build-assembly


একটি অ্যাপ অ্যাসেম্বলি তৈরি করুন

/build-integration


একটি ইন্টিগ্রেশন স্যুট তৈরি করুন


APIANT-এ একটি মাল্টি-অটোমেশন ইন্টিগ্রেশন স্যুট তৈরি করুন। যখন ব্যবহারকারী "বিল্ড অ্যান ইন্টিগ্রেশন", "ক্রিয়েট আ টু-ওয়ে সিঙ্ক", "বিল্ড আ ডেটা পাইপলাইন" বা একাধিক সমন্বিত অটোমেশন জড়িত কোনো অনুরোধ করেন, তখন এটি ব্যবহার করুন।








/build-form


একটি ফর্ম ডিজাইন করুন


APIANT অটোমেশনের জন্য একটি ফর্ম ডিজাইন করুন। যখন ব্যবহারকারী "একটি ফর্ম তৈরি করুন", "একটি ফর্ম ডিজাইন করুন", "একটি ফর্ম তৈরি করুন" বলেন, অথবা তাদের প্রয়োজনীয় কোনো ফর্মের বর্ণনা দেন, তখন এটি ব্যবহার করুন।

লাইভ অটোমেশন এবং অ্যাসেম্বলি নিরাপদে পরিবর্তন করুন: ধাপ যোগ করুন, অ্যাপ অদলবদল করুন, এন্ডপয়েন্ট পরিবর্তন করুন, সেটিংসের নাম পরিবর্তন করুন।

MCP টুল ব্যবহার করে একটি বিদ্যমান APIANT অটোমেশন সম্পাদনা করুন। যখন ব্যবহারকারী "অটোমেশন সম্পাদনা করুন", "একটি ধাপ যোগ করুন", "ম্যাপিং ঠিক করুন", "X এর পরিবর্তে Y ব্যবহার করুন", "ধাপ সরান", "ধাপ নিষ্ক্রিয় করুন" বলেন, অথবা কোনো বিদ্যমান অটোমেশনে পরিবর্তনের বর্ণনা দেন, তখন এটি ব্যবহার করুন।








/edit-assembly


একটি অ্যাসেম্বলি সম্পাদনা করুন


MCP টুল ব্যবহার করে একটি বিদ্যমান APIANT অ্যাসেম্বলি সম্পাদনা করুন। যখন ব্যবহারকারী "এসেম্বলি সম্পাদনা করুন", "JSP ঠিক করুন", "API কল আপডেট করুন", "এন্ডপয়েন্ট পরিবর্তন করুন", "একটি সেটিংয়ের নাম পরিবর্তন করুন", "ড্রপডাউন সম্পাদনা করুন" বলেন, অথবা কোনো বিদ্যমান অ্যাসেম্বলির কোড বা সেটিংসে পরিবর্তনের বর্ণনা দেন, তখন এটি ব্যবহার করুন।

3 দক্ষতা










/test-automation


একটি অটোমেশন পরীক্ষা করুন


একটি APIANT অটোমেশন শুরু থেকে শেষ পর্যন্ত পরীক্ষা ও যাচাই করুন। এটি অটোমেশনটি চালায়, ফলাফল পর্যালোচনা করে, ব্যর্থতা নির্ণয় করে, সমাধান প্রয়োগ করে, পুনরায় পরীক্ষা করে এবং ব্রাঞ্চ কভারেজ চালায়। যখন ব্যবহারকারী "এই অটোমেশনটি পরীক্ষা করুন", "একটি পরীক্ষা চালান", "অটোমেশন X কেন ব্যর্থ হচ্ছে", অথবা "অটোমেশন X নির্ণয় করুন" বলেন, তখন এটি ব্যবহার করুন।








/test-integration


সম্পূর্ণ স্যুটটি পরীক্ষা করুন


APIANT-এ একটি মাল্টি-অটোমেশন স্যুটের ইন্টিগ্রেশন টেস্ট করুন। এটি অটোমেশনগুলির মধ্যে ডেটা প্রবাহ, শেয়ার্ড স্টেটের সামঞ্জস্য, লুপ প্রতিরোধ এবং ক্রস-অটোমেশন সমন্বয় যাচাই করে। একটি ইন্টিগ্রেশন স্যুট তৈরি করার পরে অথবা যখন ব্যবহারকারী "ইন্টিগ্রেশনটি শুরু থেকে শেষ পর্যন্ত পরীক্ষা করুন" বলেন, তখন এটি ব্যবহার করুন।








/deploy-automation


ডেভ থেকে প্রোডে ডিপ্লয় করুন


ডেভ থেকে প্রোড-এ টেমপ্লেট অটোমেশন প্রকাশ করুন এবং সেগুলোকে গ্রাহক অ্যাকাউন্টগুলোতে ডেপ্লয় করুন (লিঙ্ক করা বা লিঙ্কবিহীন, ডেপ্লয়ের ক্ষেত্রে ব্যবহারকারীর পছন্দ অনুযায়ী)। যখন ব্যবহারকারী "publish", "deploy", "push to prod", বা "update customers" বলেন, তখন এটি ব্যবহার করুন।

এমসিপি বাগ রিপোর্ট করুন


যখন আপনি দেখবেন যে MCP সার্ভার নিজেই ভুল বা ত্রুটিপূর্ণ আচরণ করছে, প্রতিক্রিয়ার ধরন ভুল, ডকুমেন্টেশন এবং আচরণের মধ্যে অসামঞ্জস্য দেখা যাচ্ছে, অনিয়ন্ত্রিত ত্রুটি (unhandled errors), স্কিমা লঙ্ঘন (schema violations), প্রতিক্রিয়ায় প্রয়োজনীয় ফিল্ড অনুপস্থিত, পূর্বে কাজ করা ইনপুটে রিগ্রেশন (regression), অথবা ডকুমেন্টেশনে থাকা আচরণ বাস্তবে কাজ করছে না, তখন APIANT-এর অভ্যন্তরীণ ট্রায়েজে একটি বাগ রিপোর্ট ফাইল করুন। আপনার নিজের টুলের অপব্যবহার, ব্যবহারকারীর ভুল ইনপুট, বা প্ল্যাটফর্মের পরিকল্পিত আচরণের জন্য এটি প্রযোজ্য নয়। এটি স্বতঃস্ফূর্তভাবে করুন, যখনই দেখবেন তখনই রিপোর্টটি ফাইল করুন, ব্যবহারকারীর অনুমতি চাইবেন না। যখন আপনি "টুল ভুল ধরন দেখিয়েছে", "স্কিমা লঙ্ঘন", "এটি কাজ করার কথা কিন্তু করছে না", "সামঞ্জস্যের অসামঞ্জস্য", "MCP একটি অনিয়ন্ত্রিত ত্রুটি দেখিয়েছে", "টুলের বিবরণে X বলা আছে কিন্তু এটি Y করছে", "প্রতিক্রিয়ায় একটি প্রয়োজনীয় ফিল্ড অনুপস্থিত", "এটি আগে কাজ করত", "ডকুমেন্টেশনে থাকা আচরণটি ত্রুটিপূর্ণ", "[টুলে] রিগ্রেশন" দেখবেন, অথবা যখনই কোনো MCP-স্তরের বাগ রিপোর্ট না করে নীরবে তার সমাধান করার প্রলোভন জাগবে, তখন এটি ব্যবহার করুন।

















এমসিপি টুলস


১৩৮টি টুল। ১০টি টুলসেট। চাহিদা অনুযায়ী সক্রিয় করা হয়।


স্কিলগুলোই ওয়ার্কফ্লোকে চালনা করে। MCP টুলগুলো APIANT-এর ডেভ, প্রোড এবং ডক্স এনভায়রনমেন্টে প্রকৃত কাজটি করে। টুলগুলোকে টুলসেটে ভাগ করা হয়। শুধুমাত্র কোর সেটটিই সবসময় লোড করা থাকে; বাকিগুলো কোনো স্কিলের অনুরোধে সক্রিয় হয়, ফলে এজেন্টের কনটেক্সট সংক্ষিপ্ত থাকে এবং কার্যক্ষমতা গভীর থাকে।





ডেভেলপমেন্ট এবং প্রোডাকশন একই ১৩২-টুল সারফেস ব্যবহার করে। ডিফল্টরূপে Prod শুধুমাত্র পঠনযোগ্য; সুস্পষ্ট নিশ্চিতকরণের পর এটি রাইট গেট (write gate) হিসেবে কাজ করে। Prod সংস্করণটি দেখতে যেকোনো কার্ড টগল করুন।
