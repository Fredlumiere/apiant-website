Как это работает


Один плагин. Полный доступ к платформе.


Плагин APIANT Claude Code включает в себя три MCP-сервера и библиотеку навыков. Установите его, откройте Claude Code, и вся платформа станет доступна для взаимодействия на естественном языке.













01 · УСТАНОВКА


apiant-setup


Запустите один раз. Плагин проверяет соединения MCP, переменные окружения и версию плагина. Клод сообщает, что работает, а что отсутствует.











02 · ЗАДАНИЕ


Спросите простыми словами.


"Создайте синхронизацию Mindbody с Shopify." Клод Код выбирает нужный навык, активирует необходимый набор инструментов и начинает работу с обратной связью в режиме реального времени.











03 · КОРАБЛЬ


Разработано, протестировано, развернуто


Клод создает сборки, проводит сквозное тестирование, исправляет ошибки, развертывает в продакшене и отслеживает состояние учетной записи, не передавая управление третьим лицам.

Каждый навык представляет собой процедуру, которую выполняет опытный инженер APIANT, закодированную и исполняемую компанией Claude Code. Щелкните любую карточку, чтобы узнать полное описание того, что, когда и как.

Используйте эту инструкцию, когда пользователь произносит команды «setup», «install», «reinstall», «update plugin» или при первом запуске.













Создать


Создавайте новые сценарии автоматизации, сборки, интеграции и формы на основе подсказок, сформулированных на естественном языке.

/build-integration


Создайте набор интеграционных инструментов.

Используйте его, когда пользователь запрашивает «создать интеграцию», «настроить двустороннюю синхронизацию», «создать конвейер обработки данных» или любой другой запрос, включающий несколько скоординированных автоматизированных процессов.








/build-form


Разработайте форму


Создайте форму для автоматизации APIANT. Используйте её, когда пользователь говорит «создать форму», «разработать форму», «создать форму» или описывает необходимую ему форму.













Редактировать


Безопасно изменяйте автоматизацию и сборки в режиме реального времени: добавляйте шаги, заменяйте приложения, изменяйте конечные точки, переименовывайте настройки.

Комплексная проверка, анализ ветвей, диагностика сбоев и публикация результатов от разработки до производства.

Протестируйте и подтвердите автоматизацию APIANT от начала до конца. Выполните её, проверьте результаты, диагностируйте ошибки, примените исправления, проведите повторное тестирование и проверьте покрытие ветвей. Используйте, когда пользователь говорит «протестируйте эту автоматизацию», «запустите тест», «почему автоматизация X не работает» или «диагностируйте автоматизацию X».








/test-integration

Используется после создания набора интеграционных процессов или когда пользователь говорит: «протестируйте интеграцию от начала до конца».








/deploy-automation

Используйте эти сценарии, когда пользователь нажимает «опубликовать», «развернуть», «отправить в продакшн» или «обновить учетные записи клиентов».













Триггеры сборки


APIANT может запустить выполнение всеми возможными способами: опрос, веб-хуки (три варианта) и потоки протокола.




6 навыки










assembly-trigger-new


триггер опроса NEW_ITEM


Инструкции, специфичные для каждого типа, по созданию сборки триггера опроса NEW_ITEM. Вызывается командой /build-assembly после классификации типа.








assembly-trigger-updated


Новый или обновленный опрос


Инструкции, специфичные для каждого типа, для сборки сборки триггера опроса NEW_OR_UPDATED. Вызывается командой /build-assembly после классификации типа.








assembly-trigger-manual-webhook


Ручной веб-перехватчик


Инструкции для конкретного типа данных по созданию сборки триггера WEBHOOK (ручная регистрация). Вызывается командой /build-assembly после классификации типов.








assembly-trigger-self-registering-webhook


Веб-хук с саморегистрацией


Инструкции, специфичные для каждого типа, по созданию сборки триггера WEBHOOK_SELF_REGISTERING и сопутствующего действия удаления веб-перехватчика. Вызывается командой /build-assembly после классификации типов.








assembly-trigger-service-webhook


Веб-перехватчик сервиса


Инструкции для конкретного типа, предназначенные для создания сборки триггера SERVICE_WEBHOOK (URL-адрес веб-перехватчика на основе учетных данных с фильтрацией событий). Вызывается функцией /build-assembly после классификации типа.








assembly-trigger-protocol-thread


Протокольный поток


Специфические для типа инструкции для создания триггеров потоков протокола (PROTOCOL_THREAD_RECEIVER и PROTOCOL_THREAD). Вызываются функцией /build-assembly после классификации типа.

Операции и поддержка


Поддерживайте бесперебойную работу производственной среды: отслеживайте учетные записи, диагностируйте сбои, настраивайте поведение оповещений.




5 навыки










/monitor-account


Мониторинг клиентского счета


Отслеживайте ошибки выполнения автоматизированных процессов в учетной записи клиента на производственной среде. Используйте, когда пользователь говорит «отслеживать учетную запись», «проверить на наличие ошибок», «следить за этой учетной записью» или после развертывания автоматизированных процессов для клиента. Предназначено для периодического использования через /loop.








/support


Диагностика проблемы клиента


Диагностика проблем автоматизации клиентов, остановка некорректно работающих процессов, массовое отключение группы учетных записей в качестве аварийного выключателя (с последующим восстановлением) и создание новых учетных записей клиентов. Поиск в истории выполнения, отслеживание сбоев, извлечение HTTP-запросов, остановка неконтролируемых автоматизаций, создание снимков и отключение всех запущенных автоматизаций в родительской учетной записи и связанных с ней дочерних учетных записях, а затем их восстановление после инцидента. Создание новых учетных записей APIANT для интеграционных продуктов через admin_create_account. Claude обнаруживает несоответствие, добавляет преобразование в виде таблицы соответствия и сохраняет его как шаблон, чтобы при обратном направлении он использовался повторно.

/edit-assemblyВ действие HubSpot добавлен ограничитель скорости.


HubSpot ограничивает количество запросов до 100 за 10 секунд на одно приложение. Клод вставляет ограничитель типа «скользящее окно» на уровне сборки, а не автоматизации, поэтому каждая автоматизация, взаимодействующая с HubSpot, наследует его.


вызовы инструментов

asm_set_action_throttle({ assembly: 'hubspot.contact.update', rate: 100, window: '10s' })
asm_set_connector_throttle({ connector: 'hubspot.v3', burst: 20 })






Почему происходит ограничение скорости на уровне сборки?


Ограничение скорости для каждой автоматизации привело бы к тому, что любой другой поток HubSpot исчерпал бы бюджет. Ограничение скорости на уровне сборки (коннектор + действие) применяет лимит ко всем автоматизациям в клиенте, что является единственно правильным уровнем для общего API.

Почему это заслуживает внимания?


Ни одна другая iPaaS-платформа не работает подобным образом.


Традиционные платформы оборачивают API в пользовательский интерфейс. APIANT же оборачивает всю платформу в плагин, доступный по принципу «кода Клода». Разница видна повсюду.










SPEED


Минуты, а не спринты.


Интеграции, на которые раньше уходили недели, теперь реализуются за одну сессию Claude Code. Итерация ведется в диалоговом режиме.








QUALITY


Любой навык — это процедура.


Навыки отражают то, что делают опытные инженеры APIANT. Claude не импровизирует. Он следует проверенным инструкциям с этапами проверки.
