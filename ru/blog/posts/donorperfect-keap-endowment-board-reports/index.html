Квартальные отчеты по целевым фондам за один день: сопоставление данных о назначении доноров в DonorPerfect с данными об активности в Keap.

Fred Lumiere 14 октября 2024 г. 6 минут чтения
#НекоммерческаяОрганизация#ИдеальныйДонор#Keap#CRMConnect

Составление отчетов по целевым стипендиям — самая трудоемкая задача в сфере сбора средств на стипендии, и почти вся работа не является интеллектуальной. Сотрудник отдела развития тратит два полных дня каждый квартал на то, чтобы собрать данные о целевых пожертвованиях из DonorPerfect по фондам, вручную сопоставить их с данными об участии, экспортированными из Keap, отформатировать таблицы по каждой стипендии и отправить PDF-файлы председателям комитетов по электронной почте. Затем он повторяет это через 13 недель.

Совету директоров не нужна сложная работа. Им нужны точные цифры. Сложность работы заключается в том, что DonorPerfect знает, сколько люди пожертвовали и в какой фонд, а Keap знает, что они читали, открывали и посещали. Вся проблема заключается в том, что приходится каждый квартал вручную соединять эти две точки зрения.

Почему стандартные инструменты не справляются со своей задачей.

Большинство интеграций синхронизируют записи о донорах и на этом останавливаются. Они не сохраняют назначение пожертвования, код ограничения или идентификатор фонда в виде структурированных полей Keap. В результате Keap знает, что Джон Смит открыл весеннюю рассылку, но понятия не имеет, что пожертвование Джона в размере 50 000 долларов поддерживает стипендию для инженеров. Две части истории донора остаются разделенными, а это значит, что ежеквартальный отчет остается ручным.

Универсальные инструменты также часто упускают формулировки ограничений. Для целевых стипендий существуют юридически обязательные ограничения, которые необходимо сохранять в каждом отчете. Их потеря — это проблема соблюдения требований, а не просто проблема с данными. Аудит, выявивший неверное представление формулировок ограничений в отчете о финансировании, — это проблема, которая может положить конец карьере, а не только бюджету.

Третий недостаток — это актуальность информации. Заседания комитетов по управлению целевым капиталом часто проходят ближе к концу квартала, когда наиболее важны события последних двух недель (пожертвование крупного донора, обещание в память о ком-либо, визит председателя совета директоров для оценки деятельности фонда). Ежедневная пакетная синхронизация подходит для ежемесячной отчетности, но бесполезна для подготовки к концу квартала. Синхронизация в режиме реального времени (15 минут или меньше) позволяет отчету отражать фактическое текущее состояние, а не ситуацию прошлой недели.

Подход APIANT

CRMConnect для DonorPerfect и Keap передает метаданные фонда в виде полноценных полей Keap. Ключевые элементы для отчетности по целевым фондам:

  • Синхронизация пользовательских полей сохраняет DonorPerfect General Ledger Code, Restriction Code, Gift Purpose и Fund Designation как сохранить поля контактов и подарков.
  • CodeSync Это соответствует выпадающему списку фондов, поэтому каждая именная стипендия представляет собой структурированное значение Keap, а не строку свободного текста.
  • Подробная синхронизация информации о пожертвованиях В систему Keap вносятся данные о сумме пожертвования, его назначении и истории пожертвований каждого донора и каждого фонда.
  • Синхронизация данных в реальном времени Это позволяет поддерживать актуальность Keap настолько, что для составления квартального отчета не требуется экспорт данных из DonorPerfect в последнюю ночь.

Бетонные ступени

В качестве примера рассмотрим вымышленный стипендиальный фонд Summit Scholars Fund, связанный с университетом, который располагает 38 именными стипендиями и 5200 выпускниками-донорами. Ежеквартальный отчет будет выглядеть следующим образом:

  1. Отражайте таксономию фондов. В CodeSync сопоставьте DonorPerfect. Fund Designation и Restriction Code В пользовательские выпадающие списки Keap. 38 именных стипендий превращаются в 38 выбираемых значений.
  2. Синхронизируйте поля на уровне фонда. Включить синхронизацию для Gift Designation, Restriction Code, Gift PurposeСумма пожертвования и дата пожертвования указываются в каждой записи о пожертвовании.
  3. Создавайте представления Keap для каждой стипендии отдельно. Для каждого фонда сохранено одно представление Keap, отфильтрованное по... Gift Designation = <fund>с указанием имени донора, суммы пожертвований за все время существования фонда, даты последнего пожертвования, даты открытия последнего счета и даты последнего посещения мероприятия.
  4. Взаимодействие слоев. Встроенные в Keap данные о взаимодействии с клиентами (открытие электронных писем, клики, посещение мероприятий из календаря разработки) отображаются рядом с данными о подарках, поскольку оба показателя находятся в одной и той же записи контакта.
  5. Список крупных доноров, находящихся под наблюдением, для каждого фонда. Сохраненный вид: 20 крупнейших доноров, профинансировавших проект X, отсортированные по days since last engagementЛюбой контакт, продолжающийся более 90 дней без активности, запускает задачу Keap для назначенного сотрудника отдела развития.
  6. Сохраните язык ограничений. Для каждого фонда предусмотрено текстовое поле Keap только для чтения, содержащее ссылку на соглашение о пожертвовании и краткое описание ограничений. Оно передается вместе с каждым отчетом по фонду, поэтому председатели комитетов видят юридический контекст непосредственно в тексте.
  7. Один день, а не два дня. Специалист по разработке открывает каждое сохраненное представление, экспортирует его в PDF, прикрепляет текст с ограничениями и отправляет по электронной почте. Общее время подготовки сокращается с 16 часов до 3-4.

Исход

Репрезентативные данные по аналогичным стипендиальным фондам после применения этой схемы:

  • Время, затрачиваемое на подготовку квартального отчета, сокращается с 16 часов за цикл до примерно 4, что составляет снижение на 75 процентов.
  • Удовлетворенность председателей комитетов (измеряемая с помощью опроса после заседания) повышается, поскольку впервые учитывается контекст вовлеченности в работу над конкретными проектами, а не только финансовые показатели.
  • Отток крупных доноров выявляется за недели, а не за кварталы. 90-дневный список наблюдения позволяет выявлять проблемы до того, как они перерастут в проблемы с невостребованными пожертвованиями.
  • Время, затрачиваемое на проверку соответствия требованиям при подготовке годового отчета, сокращается, поскольку формулировки ограничений структурированы, а не скрыты в текстовом описании.
  • Качество отчетов по каждой стипендии, написанных специалистами по развитию, улучшается, поскольку данные об участии находятся рядом с данными о пожертвованиях в одном представлении, а не в папке с экспортированными CSV-файлами.

Следует отметить одну важную оговорку: это не отменяет ежеквартальную оценку работы сотрудника отдела развития. Человеку по-прежнему необходимо читать данные и писать отчет. Интеграция устраняет необходимость в работе с электронными таблицами, но не в принятии решений. Фонды, которые ожидали, что интеграция заменит должность сотрудника отдела развития, были разочарованы; фонды, которые ожидали, что она освободит сотрудника от необходимости тратить больше времени на звонки донорам и меньше времени на работу с Excel, остались довольны.

Следует уделить внимание вопросам конфиденциальности и ответственного управления данными. Получатели стипендий предъявляют иные требования к конфиденциальности, чем доноры. Истории получателей, используемые в отчетах, всегда должны предоставляться на добровольной основе с правом отзыва согласия. Многие университеты имеют специальные политики, соответствующие FERPA, относительно того, что может быть передано донорам и членам комитета; интеграция должна учитывать эти политики, структурируя данные получателей в полях, которые по умолчанию не используются в отчетах, предназначенных для членов комитета.

Что автоматизировать, а что по-прежнему требует участия человека.

Соблазн при такой интеграции — стремление к полной автоматизации отчетов. Сопротивляйтесь этому. Цифры, сводки по взаимодействию, обзоры по каждой стипендии, списки крупных доноров — автоматизируйте все это. Комментарии, объясняющие, почему одна стипендия показывает высокие результаты, а другая недофинансируется: оставьте это специалисту по развитию. Председатель совета директоров сможет отличить данные с контекстом от данных без контекста в течение первых 30 секунд после открытия отчета.

Ещё один важный момент, требующий человеческого подхода, — это рекомендация по проведению визита к потенциальному донору. Список «молчаливых» доноров на 90 дней — это сигнал тревоги, а не решение. Правильный следующий шаг для «молчаливого» крупного донора зависит от контекста, который не может быть учтен системой интеграции: недавняя личная утрата, известные жизненные перемены, ранее обсуждавшиеся предпочтения по времени. Решение принимает специалист по развитию, а не информационная панель.

Выводы строителя

  • Назначение фонда является ключом для присоединения. Без этого структурированного поля автоматизация процесса объединения помолвки и подарка невозможна.
  • Ограничения следует указывать в отдельной строке, а не в сноске. Сохранение этой информации в записи о фонде в Keap означает, что она автоматически передается со всеми отчетами.
  • Чтобы выявить скрытых крупных доноров, используйте правило 90 дней, а не ежеквартальный обзор. К моменту проведения ежеквартального собрания отношения уже охладели.
