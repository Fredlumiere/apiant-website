将 Mindbody 合同和自动付款状态实时导入 Zoho CRM

Fred Lumiere 2024年9月11日 阅读时间：5分钟
#健身与健康#身心#Zoho CRM#CRM连接#数据引擎

为什么月末合同报告毫无用处

合约会员制带来的收入是可预测的，直到自动扣款失败。但失败的窗口期很短：从扣款失败到会员悄悄寻找其他工作室，只有24到72小时。大多数工作室会在每月1号生成一份合约状态报告，这意味着3号的扣款失败会在27天内无人知晓。等到报告生成时，会员可能已经流失了。

假设：Mirror Lake Pilates（示例）是一家单店工作室，拥有 360 位合约客户。销售团队使用 Zoho CRM 管理除合同详情以外的所有信息，合同详情则保存在 Mindbody 的 PDF 文件中。每月月底的对账工作需要花费半天时间。自动付款失败的情况通常在第 28 天被发现，可能只有 30% 的客户能够追回，其余客户则流失。

为什么现成的工具在这里会失效

Mindbody 合约是嵌套对象，包含多个状态变更。大多数通用粘合工具在创建合约时获取该合约，但之后不会对其进行更新。自动付款状态、重试次数、计划变更和取消时间戳都存储在子对象中，需要调用特定的 API 才能刷新。

真正的解决方案必须：

  • 将合约视为具有动态状态的独立对象。
  • 将每次自动付款状态变更都作为近乎实时的事件推送。
  • 每天重新计算“当前状态”，作为安全保障。

自定义构建可以做到这一点，但是对 360 份合同进行每日对账的速率限制会计处理，这种事情通常会在两个月后出现问题。

APIANT 方法

CRMConnect Mindbody 到 Zoho CRM 包含一个专用接口 MB 合同 自定义对象旁边 MB 会员资格. 来自 API 应用页面：“将客户合同详情和自动付款状态持续同步到 Zoho CRM。”

具备此功能的特性：

  • 会员资格和合同同步 将 MB 合约作为专用自定义对象。
  • 实时数据同步 因此，自动付款状态的更改会在几秒钟内同步到 Zoho CRM。
  • 综合采购和支付 捕获这些信息，以便可以查询底层支付事件。
  • 自定义对象映射 因此，合同是工作流程和报告中的一流记录。

统一的数据处理引擎处理嵌套的合约有效负载，并将每个子状态清晰地映射到 Zoho 对象模式中。

MB Contracts 向 Zoho CRM 推送了哪些内容

MB Contracts 自定义对象包含实时工作流程所需的所有字段：

Zoho CRM custom object: MB Contracts
- contract_id
- contact_id (links to Zoho CRM contact)
- contract_name                e.g. "12-Month Unlimited Reformer"
- start_date / end_date
- status                       active|pending_cancel|expired|terminated
- autopay_status               current|retrying|failed|suspended
- autopay_method               card|ach
- autopay_next_charge_date
- autopay_next_charge_amount
- autopay_last_attempt_at
- autopay_last_attempt_result  success|declined|insufficient_funds|...
- autopay_retry_count
- monthly_amount
- balance_remaining

这 autopay_status 该字段是所有重要事件的触发器。状态切换为 failed or retrying工作流触发，恢复开始。

设计失败付款追回工作流程

在 MB Contracts 对象上执行 Zoho CRM 工作流程：

  1. 扳机： autopay_status 变化 current to failed or retrying.
  2. 同一时间： 自动向客户发送短信：“您好，我们的系统显示您的付款未成功。请点击此处快速更新：[update_card_link]。如果您需要帮助，请回复‘HELP’。”
  3. +4 小时： 如果状态仍然失败且客户尚未更新卡片，则为会员专员创建一个高优先级任务，并提供完整的上下文（上次成功付款、重试次数、金额）。
  4. +24小时： 工作室老板自动发送邮件：“需要我给你打个电话吗？”
  5. +48小时： 业主已创建任务，当天即可完成。
  6. 恢复分支： 什么时候 autopay_status 翻转回来 current抑制剩余任务并发送确认短信。
  7. 升级分支： 如果问题在 5 天内仍未解决，则潜在客户状态将变为“有风险的成员”，并安排面对面的客户挽留谈话。

当天通过短信就能找回大部分欠款。欠款卡通常是卡片过期或余额不足等用户不知情的情况。在几小时内（而不是几周内）发现欠款是提高找回率的关键因素。

续约日期作为管道预测

这 end_date MB Contracts 对象上的字段允许销售团队提前数周预测续约收入：

  • 90 天远期管道：总和 monthly_amount 对于与……签订的合同 end_date 未来 90 天内，按历史续约率加权计算。
  • 续约呼叫队列：与……签订的合同 end_date - now() <= 45 days 和 status = active按客户生命周期价值排序。
  • 自动续费与手动续费的区别：根据基础会员资格的续费标志进行筛选，为手动续费方面制定人员配备计划。

只有数据是实时更新的，预测才有用。月底的报告由于数据过时，预测结果会有 5% 到 15% 的误差。

Sample forecast query (Zoho CRM Reports):
  Select contact_id, monthly_amount, end_date
  From MB_Contracts
  Where end_date Between today() And today() + 90 days
    And status = 'active'
  Order By client_ltv DESC

360位客户的代表性回收率

图片仅为示意图，并非真实客户：

  • 自动付款失败恢复率基线（月底查获）：大约 25% 至 35%。
  • 通过当日短信 + 24 小时内向车主发送电子邮件，恢复率可提升至 60% 至 75%。
  • 通过及早发现故障而节省的每季度收入：在合同基础中占有相当大的比例，具体取决于平均合同规模。
  • 业主每月用于合同核对的时间从大约 4 小时减少到不到 1 小时，剩余的时间用于真正面临风险的成员。

该机制的核心在于快速检测和成员可以实际响应的序列。集成功能负责检测。序列必须如实表明请求更新。

建筑商外卖

  • 将合同和会员资格视为独立的自定义对象。一个客户可以拥有一个会员资格和三个合同（反之亦然）。每个概念一条记录，可以保持查询的简洁性。
  • 建立失败付款追回机制 autopay_status 变更事件，而非按计划报告。延迟是关键所在。
  • 使用 end_date 作为您的续约预测。这是工作室拥有的最可靠的前瞻性收入数据。
