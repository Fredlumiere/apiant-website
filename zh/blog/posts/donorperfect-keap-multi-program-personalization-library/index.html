分支机构个性化：借助 DonorPerfect 和 Keap 实现的多项目沟通策略

Fred Lumiere 2025年2月21日 阅读时间：6分钟
#非营利组织#DonorPerfect#保留#CRM连接

一个运营六个分支机构项目（儿童识字、英语作为第二语言、数字接入、青少年就业、老年人服务和创客空间）的图书馆基金会，有六位捐赠者的故事需要讲述。资助英语作为第二语言课程的捐赠者并不关心儿童识字项目的最新进展。资助创客空间的捐赠者也不关心老年人服务。然而，大多数基金会的简报都将所有捐赠者的故事混为一谈，因为Keap无法清晰地了解每位捐赠者关注的项目，而每月手动重建六份捐赠者名单也不现实。

数据已存在于 DonorPerfect 系统中。捐赠指定、项目标记以及每个项目的捐赠历史记录都已包含在内。问题在于操作层面：这些数据必须以结构化字段的形式导入 Keap，而不是以备注数据块的形式，否则项目级别的个性化设置将只能停留在理论层面。

为什么现成的工具会失败

通用连接器会将捐赠金额和捐赠日期推送到 Keap 系统，但会丢失其他信息。捐赠用途要么被忽略，要么被塞进一个自由文本字段，根本无法进行细分。由于捐赠用途没有结构化字段，“基于项目的个性化”就沦为“我们有时会记得哪些捐赠者捐赠给了哪些项目”。六个项目加上一个非结构化字段，意味着每个月都必须有人手动进行细分工作。

另一种失败模式：为六个项目分别创建六个独立的Keap受众群体。这种方法在前两周有效。到了第三个月，受众群体开始分散，一位跨项目的捐赠者同时出现在四个列表中，基金会最终不得不重新采用群发垃圾邮件或人工筛选的方式。

第三个问题是兴趣而无实际捐赠。一位参加过三次英语作为第二语言（ESL）筹款活动并向儿童识字项目捐款的捐赠者，显然对这两个项目都感兴趣。如果整合流程仅仅关注捐赠的指定用途，就会错过“与这位捐赠者谈谈ESL”这一互动信号。仅仅依赖捐赠指定用途的基金会，会错失大量升级捐赠和跨项目合作的机会。

APIANT 方法

CRMConnect for DonorPerfect and Keap 让您无需六个并行数据库即可实现程序级个性化：

  • CodeSync 与 DonorPerfect 的类似 Program Designation 下拉菜单作为 Keap 多选字段。向三个项目捐款的捐赠者，其记录中会同时包含这三个项目的信息。
  • 旗帜作为标签 将 DonorPerfect 的项目兴趣标记转换为 Keap 标签。兴趣可能并非一定体现在捐赠上（例如志愿服务时长、活动参与），因此，标记和标识结合起来比单纯的捐赠更能全面地反映捐赠者的兴趣。
  • 详细捐赠信息同步 在捐赠者记录中保留每个项目的捐赠历史（终身捐赠给扫盲项目、终身捐赠给 ESL 项目）。
  • 实时数据同步 意味着指定的捐赠会在几分钟内触发相关的程序。

混凝土台阶

以虚构的城市图书馆基金会——遗产图书馆基金会为例，该基金会拥有 2800 名捐赠者，涵盖 6 个分支机构，其个性化流程如下所示：

  1. 地图程序名称。 在 CodeSync 中，镜像 Program Designation 作为 Keap 多选下拉菜单，包含六个值。镜像 Program Interest Flag 单独作为另一个多选选项。
  2. 同步每个项目的捐赠字段。 自定义字段 Lifetime Giving - Literacy, Lifetime Giving - ESL等等，数据来自 DonorPerfect 的总数。
  3. 打造一份动态的月度电子报。 Keap 的单封邮件，包含条件内容块。识字模块仅在满足特定条件时显示。 Program Designation contains Literacy OR Program Interest Flag contains Literacy每个程序都采用相同的模式。
  4. 触发针对特定项目的申诉。 当收到指定捐赠时，Keap 会启动一个专门针对该项目的感谢序列：一位新的扫盲捐赠者会听到阅读伙伴计划的成果；一位新的 ESL 捐赠者会听到公民班毕业典礼的消息。
  5. 妥善处理跨项目捐赠者事宜。 捐赠者如果指定了两到三个捐赠用途，每月邮件中会显示所有相关的感谢信息，但每笔捐赠只会收到一封感谢邮件（由最近一次的捐赠用途触发）。避免出现“一周内收到六封感谢邮件”的情况。
  6. 将印刷品与数码产品进行协调。 当一个分支机构发送直接邮件募捐请求时，Keap 会阻止同一捐赠者在同一时间段内收到数字募捐请求，以免他们在同一周内收到同一项目的两次募捐请求。
  7. 每个项目的投资回报率报告。 Saved Keap 报告按以下方式分组 Program Designation：获取捐赠者的成本、二次捐赠率、平均捐赠额，每月反馈给各分行经理。

结果

完成这项连接后，来自类似中型图书馆基金会的代表性数据：

  • 由于内容模块与每位读者都相关，每月新闻简报的平均打开率提高了约 8-12 个百分点。
  • 指定捐赠保留率（在 12 个月内再次向同一项目捐赠）通常比未区分的基线高出 10-15 个百分点。
  • 分行经理不再向发展办公室索取月度报告，因为他们对 Keap 有既定的看法。
  • 跨项目捐赠者如果发现其第一个项目方向的工作与第二个项目互补，则更常向第二个项目捐款。
  • 由于基金会可以向指定项目捐赠者发送有针对性的印刷宣传材料，而不是向所有捐赠者发送邮件，因此直邮印刷成本下降了。

现实的上限是：节目个性化固然重要，但并非全部。主题、故事质量和播出时间仍然是决定节目开播率的关键因素。整合消除了“一刀切”的结构性障碍。

在图书馆基金会，选择退出机制至关重要，因为许多捐赠者都是社区的长期成员，他们期望得到体贴周到的对待。“尊重捐赠者意愿”确保了这一点。 Do Not Email 任何针对特定项目的退出选项（例如“仅对识字项目感兴趣”）在两个系统中均得到尊重。如果捐赠者告知基金会他们只想了解儿童识字方面的信息，则不应收到任何关于英语作为第二语言（ESL）的募捐信息。整合功能的作用就在于确保这一点，而无需营销团队记住每位捐赠者的偏好。

频道混合和时序

大多数图书馆基金会都会同时发送纸质和电子邮件宣传材料。当纸质和电子版宣传材料共享同一数据源时，整合的价值将更加显著。例如，一位捐赠者如果在三月初收到了儿童识字纸质宣传材料，那么他/她就不应该在同一周收到儿童识字电子版宣传材料。可以使用同步项目标识进行协调：一周发送纸质宣传材料，下一周发送电子版，系统会自动处理屏蔽操作。

印刷募捐信也能受益于针对特定用途的文案。信函的封面保持不变，内页和捐赠表格则根据捐赠者的主要捐赠项目而变化。捐赠者收到的信件仿佛是专门为他们撰写的，因为从某种意义上说，的确如此。虽然每份信件的印刷成本可能会略有上升，但每筹集一美元的成本却会下降。

时机在各个渠道都至关重要。各分部经理通常希望围绕各自项目的里程碑事件（例如暑期阅读启动、秋季ESL课程招生、假日数字资源获取活动）开展针对性宣传活动。集成方案中的项目指定字段使得这些分部主导的日程安排成为可能，而无需每个分部都建立自己的营销基础设施。发展部门由此成为协调者，而非瓶颈。

建筑商外卖

  • 指定为多选，而非单选。 真正的捐赠者会向多个项目捐款；如果将其建模为单一选择，则会迫使人们做出难看的妥协。
  • 一封动态邮件胜过六封分段式邮件。 六份并行发送的电子报意味着六轮审批、六种版面设计，六次出错的机会。条件模块可以扩展。
  • 打印过程中抑制数字信号。 跨渠道协调是深思熟虑和疲惫不堪之间的区别。
