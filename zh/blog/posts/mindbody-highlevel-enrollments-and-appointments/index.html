为什么道场会有三个日程安排界面？

武术学院几乎总是同时运行三种课程安排模式：

  • 入学人数 适用于儿童或初学者课程（为期 8 周的入门课程，家庭需提前承诺参加）。
  • 课程 高级课程（为期 12 周的固定日期比赛准备模块）。
  • 预约 用于私人课程、评分和评估。

Mindbody 支持这三种功能，但它们位于平台的不同层面。当你将数据推送至 CRM 系统时，大多数集成只会获取其中一种（通常是课程），而忽略其他功能。结果就是：自认为掌握学生全部课表的高级自动化流程，实际上只掌握了三分之一的信息。

假设：River Bend Brazilian Jiu Jitsu（示例）是一家拥有180名学员的单道场巴西柔术学院。他们开设入门课程、高级课程和私人课程。学院负责人通过HighLevel发送课程提醒，但经常收到“我5:30和Marco教授有私人课程，为什么还要提醒我6点的课？”这样的回复。这些提醒是基于部分数据运行的。

为什么现成的工具会忽略这一点

Mindbody 的报名、课程和预约 API 是独立的。如果使用一个只监听课程事件的粘合工具，则会完全忽略报名事件。如果使用一个只监听预约事件的工具，则会错过类似课程的多周预订。虽然可以自行构建这三个流程，但每个流程都有各自的速率限制和特殊情况（例如课程出勤与课程完成、报名退课与转课、私人课程改期等）。

整合至关重要，因为…… 学生 系统只能看到一个日程安排。客户关系管理系统也应该如此。

APIANT 方法

CRMConnect Mindbody 到 HighLevel 涵盖了所有三个日程安排界面：

  • 班级和约会日历同步 课程预订、预约、报名和课程安排，所有信息都会导入 HighLevel 日历，并可准确跟踪下次预订情况。
  • 注册和课程预订同步 作为一项专门的特色，因此需要花费数周时间才能完成，而且这些工作都取得了卓越的成绩。
  • 全面的访问和活动同步 因此，这三个方面的出勤情况都会记录在学生的个人资料中。

统一的数据处理引擎将三个身心表面在高级层面上规范化为一致的形状。学生的高级接触点只有一个。 mindbody_next_session_at 无论下一次会议是课堂、私人会议还是课程会议，都应参加。

注册和课程同步为 HighLevel 增添了哪些功能

学生档案包含统一的信息：

HighLevel contact custom fields:
- mindbody_active_enrollments        list of enrollment names
- mindbody_active_courses            list of course names
- mindbody_next_session_at           ISO timestamp (across all surfaces)
- mindbody_next_session_type         class|appointment|course|enrollment
- mindbody_next_session_instructor   string
- mindbody_next_session_location     string

Custom object: Mindbody Enrollment
- enrollment_id
- enrollment_name
- start_date / end_date
- weekly_schedule
- attendance_count / sessions_total
- status: active|completed|dropped

Custom object: Mindbody Course
- course_id
- course_name
- start_date / end_date
- meeting_dates              list of ISO timestamps
- attendance_count / meetings_total

这 mindbody_next_session_at 该字段是统一视图。它基于所有三个界面进行计算并实时更新。提醒功能均基于此统一字段运行。

为每个学生设计一个日历视图

高级自动化提醒功能将流程简化为一个流程，而不是三个流程：

  1. 扳机： 按时间计费，每小时根据接触情况运行 mindbody_next_session_at 接下来24小时内。
  2. 分支 mindbody_next_session_type:
  3. class：发送标准的“今晚有课”短信，并附上授课老师的姓名。
  4. appointment：发送“与[指导老师]私教”短信，并附上房间/空间信息。
  5. course：发送“今晚进行模块 4 课程，请带上笔记”短信，并附上课程详情。
  6. enrollment发送“基础知识第 5 周”短信。
  7. 请在课程开始后等待30分钟。
  8. 出席活动分支： 存在、不存在或尚未发生事件。
  9. 缺失分支： 第二天，短信：“我们想念你了，你想改到周六上课吗？”

学生只会收到一次关于下次课程的提醒，而不是针对三个不同平台的三次相互冲突的提醒。

在顶部叠加下一个预约跟踪

对于既有常规课程又有定期私教课程的学生来说，下次课程的日期可能在同一天内发生变化。集成方案通过始终返回所有平台上最早的下次课程来解决这个问题。因此：

  • 周三上午： mindbody_next_session_at 指向下午 5:30 与马可教授的私人会面。
  • 下午 5:30 开始记录出勤情况：场地切换到晚上 7 点的高级班。
  • 晚上 7 点之后：场地将转为周四上午的报名环节。

业主自动化系统无需知道下一个会话将在哪个表面上进行。集成系统会自动计算。

Computation rule (handled by CRMConnect, not by the operator):
  next_session_at = min(
    next_class_booking,
    next_appointment_booking,
    next_course_meeting,
    next_enrollment_meeting
  )

代表 180 名学生节省了排课时间

图片仅为示意图，并非真实客户：

  • 业主每周花费大约 3 到 5 个小时来协调课程、预约和报名等提醒安排，这些时间已被收回。
  • “为什么提醒我一门我没上的课？” 回复：明显下降，因为提醒尊重了实际的下一节课。
  • 私人课程出勤率：提高了 4 到 7 个百分点，因为提醒信息发送到了正确的位置。
  • 课程中期（第 5 周）的退学率显著下降，因为出勤率能更快地发现缺席的学生。

该升降机是机械式的。“下一节课”的信息来源由一个取代了三个。

建筑商外卖

  • 将注册、课程和预约视为一等公民，而不是“类”的变体。学生并不关心他们的会话在哪个界面进行，客户关系管理系统（CRM）也不应该关心。
  • 计算单个 next_session_at 该字段为所有表面的最小值。每个下游提醒都从该字段读取数据。
  • 使用自定义对象来管理注册和课程，这样就可以查询出勤率和课程状态，而不仅仅是存储它们。
