危機対応寄付者をニュースサイクルを超えて維持する：Keapにおける寄付停止者の回復シーケンス

Fred Lumiere 2025年2月3日 6分で読めます
#非営利団体#ドナーパーフェクト#キープ#CRMConnect#双方向同期

危機対応型の寄付者は、非営利団体の資金調達において最も離脱率の高い層です。ある人が火曜日に難民再定住の緊急事態に関する記事を読み、水曜日に100ドルを寄付し、春までには寄付をやめてしまう、といった具合です。問題自体は解決していません。報道が途絶えただけです。緊急時における支援から継続的な関与へと意図的に橋渡しをしなければ、寄付者は再び支援する理由を見出せないのです。

危機的状況下での寄付金獲得に頼っている団体にとって、この離脱率は集客ファネルにおける最大の漏れと言える。この問題を解決するためのデータはDonorPerfectに存在する。元の寄付に付けられたアピールコードによって、寄付者が危機的状況下で獲得された寄付者であることがわかる。Keapは、回復処理を実行するためのシステムだ。この2つのシステムが連携しなければ、回復は実現しない。

市販のツールが失敗する理由

標準的な同期ツールは寄付記録を送信するだけで、Keapがセグメント化できるようなアピールコード、勧誘コード、ソースチャネルを保持しません。その結果、Keapのオーディエンスは「寄付者」で埋め尽くされ、危機的状況下での寄付、年末の寄付、イベントなど、どの方法で寄付が集まったのかを区別する方法がありません。危機的状況下での寄付者と毎月定期的に寄付をする寄付者は同じように扱われるため、どちらの方向へのメッセージングも効果を発揮しません。

2つ目の問題点は、寄付者の実際の寄付頻度ではなく、カレンダーに基づいてリカバリーシーケンスが実行されてしまうことです。14ヶ月ごとに寄付をしている寄付者は、12ヶ月目に寄付が途絶えたわけではありませんが、一律の「年間リマインダー」では、寄付が途絶えたかのように扱われてしまいます。これを正しく行うために必要なデータ（最終寄付日、総寄付額、アピールコード、寄付の用途）は、Keapが読み取れる寄付者属性として流れてくる必要があります。

3つ目の課題は言語です。難民支援機関は、自身も難民として到着した寄付者を支援することが多く、中には英語よりもスペイン語、アラビア語、ウクライナ語、ベトナム語を好む単一言語話者の寄付者もいます。汎用コネクタでは優先言語コードが削除されるため、復旧メールはデフォルトで英語になり、寄付者はメールを開かなくなります。このフィールドを保持することは、範囲は小さいものの、大きな効果をもたらします。

APIANTアプローチ

CDN Connect for DonorPerfectとKeapはデータ部分を解決し、ワークフロー部分はネイティブのKeapによって処理されます。

  • CodeSync DonorPerfectのアピール、勧誘、ソースコードをKeapにドロップダウンカスタムフィールドとして反映します。危機によって獲得したオーディエンスは、推測ではなく、Keapのセグメントとして登録されます。
  • 詳細な寄付情報同期 DonorPerfectの変更に応じて更新される、最終寄付日、総寄付額、最大寄付額、および寄付件数をKeapの連絡先フィールドにプッシュします。
  • 双方向同期 Keap に書かせよう reactivated 復旧が成功したら、DonorPerfectにタグを戻して、翌年のターゲティングのためのループを閉じます。
  • タグとしてのフラグ 通信設定フラグ（優先言語、勧誘拒否、役員）を明示することで、復旧シーケンスがそれらを自動的に尊重するようにします。

具体的なステップ

架空の地域機関であるニュー・ルーツ・リセットルメント・サービスを例にとると、1,900人のアクティブな寄付者と多言語の寄付者基盤を持つこの機関における復興の流れは次のようになります。

  1. 出典元を明記してください。 CodeSyncでは、DonorPerfectをミラーリングします。 Appeal Code Keap ドロップダウンとして。危機アピールコード（例： 2025-WINTER-EMERG, 2025-CONFLICT-RESP) は第一級の Keap 値になります。
  2. ライフサイクルフィールドを同期します。 各寄付者レコードについて、初回寄付日、最終寄付日、寄付総額、最高寄付額、および優先言語を有効にしてください。
  3. セグメントを構築する。 動的リストの維持: Appeal Code contains "EMERG" OR "CRISIS" OR "RESP" AND Last Gift Date is more than 6 months ago AND Total Gifts <= 2.
  4. 3段階のリズム。 6か月経過したら、当機関が支援した移住家族からのストーリー主導型の近況報告を送付します（ストーリー掲載には明確な同意を得ており、許可なく個人を特定できる情報は掲載しません）。9か月経過したら、プログラムの成果に関する報告と、毎月の寄付をお願いするメッセージを送付します。12か月経過したら、担当者名を明記したメッセージを送り、電話での面談を提案します。
  5. 多言語対応のパーソナライゼーション。 優先言語フィールドは、同じシーケンスのスペイン語、アラビア語、またはウクライナ語のコピーをルーティングします。Keapのメールマージフィールドがこれを処理します。統合は言語コードを最新の状態に保つだけです。
  6. 賢明に抑制せよ。 Flags-as-Tags は、以下の寄付者を除外します。 do-not-solicit理事会メンバー、および自動化されたアウトリーチ活動を通じて主要な寄付者を積極的に開拓しているすべての人。
  7. ループを閉じる。 回復ギフトが届くと、双方向同期は reactivated-2026 DonorPerfectにタグを戻してください。来年のセグメンテーションに活用できます。

結果

このシステムを導入した後の、同規模の中規模再定住支援機関の代表的な数値は以下のとおりです。

  • 危機的状況下で獲得した寄付者の12か月後の回復率は、約8％（危機的状況下で一度だけ寄付をした人の業界基準値）から18～22％に上昇する。
  • 危機的状況下で獲得した寄付者1人あたりの24か月間の維持価値は、寄付者が完全に寄付を中止する前に6か月目の接触があった場合、およそ3倍になる。
  • 四半期ごとの寄付停止者への連絡に必要なリストの手動抽出時間が、6時間から0時間に短縮されます（リストは自動的に更新されます）。
  • 多言語を話す寄付者には英語のみのフォローアップメールが届かなくなるため、それだけでも英語圏以外の層では開封率が30～40％向上する傾向がある。
  • 6か月後の連絡には反応を示さなかったものの、9か月後のストーリー更新に反応を示した寄付者は、「ストーリー反応者」として識別され、今後のキャンペーンの順序付けのためにタグ付けされる。

18～22％の回復率が現実的な上限です。ここでは、頻度よりもストーリーが重要です。罪悪感を煽るようなコンテンツは逆効果ですが、明確な同意を得たストーリー主導型のコンテンツは効果を発揮します。危機をきっかけに獲得した寄付者で、一度寄付をした後、二度と関わらない人は、どんな手法を用いてもほとんど回復できません。重要なのは、適切なタイミングで適切な働きかけを一度行うだけで関心を持ち続けていたはずなのに、沈黙によって失われてしまった15～20％の人たちを再び引きつけることです。

プライバシー保護は譲れない事項です。支援要請メールで使用する記事は、記載されている人物から明確な同意を得ている必要があり、同意はいつでも撤回できます。氏名、正確な場所、子供の写真などの個人情報は、家族から明示的に要請がない限り、匿名化または一般化して使用する必要があります。この統合によりターゲティングが可能になりますが、受益者を保護するという機関の義務が軽減されるわけではありません。

避けるべきよくある間違い

リカバリーシーケンスが稼働したら、注意すべきパターンがいくつかあります。プロセッサエラーが自然に解消された場合は、リカバリーをトリガーしないでください。銀行が再試行に成功した一時的な定期課金の失敗は、支払いの失敗とはみなされません。これを失敗として扱うと、送金者が混乱し、指標が汚染されます。一時的な障害がシーケンスの起動前に解消されるように、支払い失敗ロジックに7日間の遅延バッファを組み込んでください。

12ヶ月間の回復支援と年末の年間募金活動が重複しないようにしてください。危機的状況下で獲得した寄付者が12ヶ月目を迎えたのが12月初旬だった場合、回復支援と年末の年間募金活動が同じ週に届くことになります。カレンダーを調整するか、どちらか一方を優先して、その寄付者にとってどちらがより効果的かを判断してください。

ストーリーの内容が文化的な適合性を持つかどうかを確認してください。世界のある地域から移住してきた家族と、別の地域から移住してきた家族では、露出に対する期待が大きく異なる場合があります。英語のストーリーを翻訳することと文化的な翻訳は同じではありません。多言語コンテンツを大規模に展開する前に、コミュニティの担当者と連携してください。

建築業者の持ち帰り

  • アピールコードはセグメントであり、寄付金額ではありません。 緊急支援募金への25ドルの寄付は、年末募金への25ドルの寄付とは扱いが異なります。コードを同期しないと、対象グループを特定できません。
  • 3つの窓は、年に一度のリマインダーよりもずっと良い。 6ヶ月、9ヶ月、12ヶ月のメールは、それぞれ準備段階の異なる様々な寄付者を捉えることができる。しかし、年1回のメールでは、どの寄付者にも届かない。
  • 必ず復旧結果を報告してください。 なしで reactivated DonorPerfectにタグ情報が流れてしまうと、次のサイクルでどの回復ドナーを異なる方法で治療すべきかを示す唯一のシグナルが失われてしまいます。
