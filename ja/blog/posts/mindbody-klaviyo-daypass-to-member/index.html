デイパスの帰属問題

デイパスは、クライミングジム、ヨガスタジオ、その他あらゆるドロップイン型フィットネス施設への最も安価で一般的な入り口です。しかし、顧客獲得ファネルの中で最も追跡が難しい部分でもあります。来店客はデイパスを購入し、2時間クライミングをして帰り、3週間後に会員になるか、二度と戻ってこないかのどちらかです。このコンバージョン率が5%なのか25%なのかによって、顧客獲得戦略全体が左右されるはずです。しかし、ほとんどの運営者はどちらなのかを把握していません。

仮に、Basalt and Belay Climbing Co（例）は、会員数1,100人のジムで、日帰り利用の顧客もバランスよく利用しているとします。Klaviyoアカウントには、すべてのメール購読者とすべての会員登録者が登録されています。しかし、この2つの間に明確なリンクがありません。日帰り利用、2回目の利用、3回目の利用、そして最終的な会員登録は、Klaviyoにとっては4つの別々のイベントであり、単一の識別子に結び付けられていません。

既製ツールがここで失敗する理由

識別子の共有問題は実際に存在します。Mindbodyは最初の取引時にクライアントIDを割り当てますが、同じユーザーが翌日のパスを少し異なるメールアドレス（別のブラウザによる自動入力、またはゲストチェックアウトなど）で購入した場合、Mindbodyは重複したIDを作成します。その結果、Klaviyoは2つのプロファイルを認識します。コンバージョン計算が破綻するのは、分析段階ではなく、重複排除段階です。

Zapやカスタムスクリプトはメールアドレスの照合はできる場合もありますが、名前と電話番号の組み合わせで確実に重複を排除することはできず、後でプロファイルが統合された際に訪問回数を照合することもできません。統合自体は可能ですが、重複排除と訪問回数の照合が、ほとんどの構築作業の行き詰まりの原因となっています。

APIANTアプローチ

CRMConnect Mindbody to Klaviyoは、連携して動作する2つの機能でこれを処理します。

  • 来店追跡 最近の顧客訪問を記録し、毎日照合を行うことで、再入力または統合された記録によって重複した訪問イベントが作成されないようにします。
  • 購入・売上明細の同期 デイパスの購入を、会員登録時のSKUとは別に、SKUを保持したまま構造化されたイベントとして記録します。

Klaviyo側では、プロフィールはメールアドレスに基づいて照合され、その場で更新されます。後日Mindbodyの記録が統合された場合、統合された履歴が反映されます。その結果、実際のユーザーごとに1つのKlaviyoプロフィールが作成され、1日パスの購入、訪問回数、そして最終的な会員登録といったすべての履歴が同じタイムライン上に記録されます。

Klaviyoで訪問者追跡機能がどのように動作するのか

各プロファイルには、デイパスの利用状況を特定するための属性セットが継続的に付与されています。

Klaviyo profile attributes:
- mindbody_first_purchase_sku        e.g. DAYPASS-ADULT
- mindbody_first_visit_at            ISO timestamp
- mindbody_visit_count               int
- mindbody_last_visit_at             ISO timestamp
- mindbody_membership_status         active|expired|none
- mindbody_membership_started_at     ISO timestamp (null until conversion)

あなたが気にしているコンバージョンイベントは、 mindbody_membership_started_at プロファイルのタイムスタンプを null から反転します。 mindbody_first_purchase_sku 一日パスだった。このたった一つの比較こそが、「一日パス購入者のうち、何人が会員になったか」という問いへの答えだ。

日帰りパスからビジターへのコンバージョンフローの設計

属性が設定されれば、あとは流れは簡単です。

  1. トリガー： Mindbodyの1日パス購入イベント。
  2. 4時間待ってください。 同日登山の状況。
  3. メール1（登山当日の夜）： 「セッションがうまくいったことを願っています。7日間有効の再利用パスを5ドル割引でご提供します。」
  4. ブランチ mindbody_visit_count 7日後：
  5. もう一つの方法：初心者向け講習会のご案内とともに「最初の登りが一番難しい」というメールを送る。
  6. 2～3：会員比較を添えて「あなたはハマっています」というメールを送信します。
  7. 4人以上の場合、会員制と一日パスの損益分岐点を記載した「計算してみましょう」メールを送信します。
  8. 抑制する mindbody_membership_status = active. 改宗した人へのしつこい勧誘をやめる。

3つ目のカテゴリーは、コンバージョン率の高い層です。1週間に4回、1日パス料金を支払ってサイトを訪問している人は、まだ会員登録をしていないものの、会員である可能性が高いと言えます。メールの内容はほぼ自動的に作成されます。

コンバージョンレポートを正直に読む

1日パスの後に続くすべての会員登録を数えてしまいがちですが、正確な数はもっと少ないです。Klaviyoで以下のセグメンテーションを使用してください。

  • コホート： 暦月Nのデイパス購入者。
  • ウィンドウ： 初回購入日から60日間。
  • 変換された： mindbody_membership_started_at 範囲内に収まる。

30日間コンバージョンと60日間コンバージョンの2つの比率を報告してください。60日を超えるものは別のマーケティングストーリーであり、デイパスチャネルの成果として計上すべきではありません。期間を「一度でも」短縮する事業者は、このチャネルの成果を2倍以上過大評価しています。

会員数1,100人における代表的なコンバージョン率

あくまでも参考例であり、実際の顧客像ではありません。

  • 30日間のデイパスから会員へのコンバージョン率の基準値（ターゲットとなる顧客フローなし）：約4～7パーセント。
  • 上記の流れにおける30日間のコンバージョン率：9～14％の範囲に上昇。これは主に、オファーのタイミングが適切である2～3回訪問および4回以上の訪問セグメントからのものです。
  • 新規登録前の会員一人当たりの平均デイパス枚数：2.6枚（これはフロントデスクが会話を始めるべきポイントを示す有用な数値です）。

価格設定、登山者の属性、そして日帰りパスから会員制への移行に伴う料金体系の厳しさによって、数字は変動します。仕組みは同じです。

ビルダーテイクアウト

  • このゲームの鍵は共有識別子にあります。統合レイヤーでメールベースの重複排除を正しく実装しないと、後続の処理で計算が全く機能しません。
  • 使用 mindbody_visit_count 分岐点として重要なのは、初回訪問からの日数ではなく、週2回の訪問です。会員登録意向を示す指標としては、月2回の訪問よりも週2回の訪問の方が優れています。
  • コンバージョン期間を30日または60日に限定しましょう。「永久」というのは、実際にはそのチャネルが機能しなくなる時点を隠すための、都合の良い言い訳です。
