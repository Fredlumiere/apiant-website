支店ごとのパーソナライゼーション：DonorPerfectとKeapを活用したマルチプログラムコミュニケーション戦略

Fred Lumiere 2025年2月21日 6分で読めます
#非営利団体#ドナーパーフェクト#キープ#CRMConnect

6つの分科会プログラム（児童識字教育、ESL、デジタルアクセス、青少年就労支援、高齢者サービス、メイカースペース）を運営する図書館財団には、6つの寄付者の物語があります。ESLクラスに資金を提供している寄付者は、児童識字教育の最新情報には興味がありません。メイカースペースに資金を提供している寄付者は、高齢者サービスには関心がありません。しかし、ほとんどの財団のニュースレターでは、すべての寄付者をひとまとめにして扱っています。なぜなら、Keapには各寄付者がどのプログラムに関心を持っているかを明確に把握する機能がなく、毎月6つのリストを手作業で作り直すのは現実的ではないからです。

データはDonorPerfectに存在します。寄付の指定、プログラムフラグ、プログラムごとの寄付履歴などがすべてそこにあります。問題は運用面です。そのデータはメモの羅列ではなく、構造化されたフィールドとしてKeapに取り込まれる必要があり、そうでないとプログラムレベルのパーソナライゼーションは理論上のものにとどまります。

市販のツールが失敗する理由

汎用コネクタは寄付金額と寄付日をKeapに送りますが、それ以外の情報は失われます。寄付の指定は削除されるか、誰もセグメント化できない自由記述欄に押し込まれます。構造化されたフィールドとして指定がない場合、「プログラム認識型パーソナライゼーション」は「どの寄付者がどのプログラムに寄付したかを時々覚えている」というレベルにまで低下します。6つのプログラムと非構造化フィールドでは、毎月誰かが頭の中でセグメンテーション作業を行わなければなりません。

もう一つの失敗例は、6つのプログラムに対してそれぞれ異なるKeapオーディエンスを設定することです。これは2週間はうまくいきますが、3ヶ月目にはオーディエンスが分散し、複数のプログラムに寄付する人が同時に4つのリストに登録され、財団はスパムメールの一斉送信か手作業によるキュレーションのどちらかに戻らざるを得なくなります。

3つ目の問題は、寄付を伴わない関心です。ESLの資金調達イベントに3回参加し、児童識字教育にも寄付をした寄付者は、両方のプログラムに真に関心を持っています。もし統合システムが寄付の指定項目しか見ていない場合、「この寄付者にESLについて話してみよう」というエンゲージメントシグナルを見逃してしまうことになります。寄付の指定項目だけに頼っている財団は、アップグレードやプログラム間の連携といった大きな機会を逃してしまうのです。

APIANTアプローチ

DonorPerfectとKeap向けのCRMConnectは、6つの並列データベースを使用することなく、プログラムレベルのパーソナライゼーションを実現します。

  • CodeSync DonorPerfectの Program Designation ドロップダウンリストを複数選択可能なKeapフィールドとして使用します。3つのプログラムに寄付をした寄付者は、その記録に3つの値すべてが登録されます。
  • タグとしてのフラグ DonorPerfectのプログラム関心フラグをKeapタグに変換します。関心は寄付を伴わなくても存在する可能性があるため（ボランティア活動時間、イベント参加など）、フラグと指定を組み合わせることで、寄付だけの場合よりも詳細な状況を把握できます。
  • 詳細な寄付情報同期 寄付者の記録には、プログラムごとの寄付履歴（識字教育への生涯寄付額、ESLへの生涯寄付額など）が保存されます。
  • リアルタイムデータ同期 指定された寄付が行われると、数分以内に該当するプログラムが開始されることを意味します。

具体的なステップ

架空の都市図書館財団であるヘリテージ図書館財団（6つの支部プログラムに2,800人の寄付者がいる）を例として挙げると、パーソナライゼーションの流れは次のようになります。

  1. 地図上のプログラム指定。 CodeSyncでは、ミラー Program Designation Keapの6つの値を持つ複数選択ドロップダウンとして。ミラー Program Interest Flag 別の複数選択項目として別々に扱う。
  2. プログラムごとの寄付項目を同期します。 カスタムフィールド Lifetime Giving - Literacy, Lifetime Giving - ESLなど、DonorPerfectの合計値からデータが取得されます。
  3. 毎月更新される、魅力的なニュースレターを作成しましょう。 条件付きコンテンツブロックを含む単一のKeapメール。リテラシーブロックは、 Program Designation contains Literacy OR Program Interest Flag contains Literacy各プログラムで同じパターン。
  4. プログラム固有の異議申し立てをトリガーする。 指定された寄付が入ると、Keapはそのプログラムに特化した感謝のメッセージを送ります。例えば、識字教育への新規寄付者には読書パートナー活動の成果を、ESL（第二言語としての英語）への新規寄付者には市民権取得講座の卒業式について伝えます。
  5. 複数のプログラムにまたがる寄付者には、丁寧に対応しましょう。 2つまたは3つの指定先を持つ寄付者には、毎月のメールで関連するすべてのブロックが表示されますが、寄付ごとに1つの感謝メールシーケンスのみが送信されます（最新の指定先によってトリガーされます）。「1週間に6通の感謝メールが届く」という失敗パターンを避けましょう。
  6. 印刷物とデジタルコンテンツを連携させる。 支部がダイレクトメールで寄付のお願いを送ると、Keapは同じ期間内に同じ寄付者に対してデジタルでの寄付のお願いをしないように設定し、同じ週に同じプログラムへの寄付のお願いが2回届くのを防ぎます。
  7. プログラムごとの投資対効果（ROI）レポート。 保存された Keap レポートをグループ化 Program Designation：獲得した寄付者一人当たりのコスト、2回目の寄付率、平均寄付額は、各支店長に毎月報告されます。

結果

この配線工事を行った後の、同規模の中規模図書館財団の代表的な数値は以下のとおりです。

  • 月刊ニュースレターの平均開封率は、コンテンツブロックが各読者にとって関連性のあるものとなるため、およそ8～12ポイント上昇する。
  • 指定寄付の継続率（12ヶ月以内に同じプログラムに再度寄付する）は、通常、区別なしの基準値よりも10～15ポイント上昇する。
  • 支店長たちは、Keapの定型的な見解を持っているため、開発部門に月次報告書を求めるのをやめた。
  • 複数のプログラムに寄付する人は、最初のプログラムの活動内容と相補的な研究成果が見つかった場合に、2つ目のプログラムにも寄付する頻度が高くなる。
  • 財団は、全リストへの郵送ではなく、特定のプログラムの寄付者を対象とした印刷物による寄付の呼びかけを行うことができるため、ダイレクトメールの印刷コストが削減されます。

現実的な限界：プログラムのパーソナライズは効果の大部分を占めるが、全てではない。件名、ストーリーの質、タイミングは依然として開封率を左右する。統合によって、画一的なアプローチをとる構造的な理由がなくなる。

オプトアウトのストーリーは、図書館財団にとって重要です。多くの寄付者は長年の地域住民であり、思いやりのある対応を期待しているからです。寄付者の意向を尊重することで、 Do Not Email また、プログラム固有のオプトアウト（「識字プログラムのみに関心がある」など）は、両方のシステムで尊重されます。財団に、子どもの識字能力に関する情報のみを希望すると伝えた寄付者には、ESL（第二言語としての英語）に関する寄付のお願いが送られるべきではありません。この統合システムの役割は、マーケティングチームがすべての希望を記憶する必要なく、その希望を確実に反映させることです。

チャンネルミックスとタイミング

ほとんどの図書館財団は、印刷物と電子メールの両方を送信しています。印刷物とデジタル版が同じ情報源に基づくセグメンテーションを共有している場合、統合の価値はさらに高まります。3月上旬に児童識字教育に関する印刷物の寄付依頼を受け取った寄付者は、同じ週に児童識字教育に関するデジタル版の寄付依頼を受け取るべきではありません。同期プログラム指定を使用して、1週間は印刷物、次の週はデジタル版を送信し、配信停止は自動的に処理されるように調整してください。

印刷物による募金活動も、寄付の目的を考慮した文章作成によって効果を発揮します。表紙の体裁はそのままに、同封物や寄付申込書は寄付者の主要な寄付プログラムに基づいて変更されます。寄付者は、まるで自分宛てに書かれたかのような郵便物を受け取ることになります。実際、ある意味ではまさにその通りなのです。印刷コストは1通あたり若干上昇するかもしれませんが、1ドルあたりの寄付額は減少します。

タイミングはあらゆるチャネルにおいて重要です。支店長は、各支店のプログラムの節目（夏期読書キャンペーン開始、秋期ESL登録、年末年始のデジタルアクセスキャンペーンなど）に合わせて、プログラム固有のキャンペーンを展開したいと考える傾向があります。この統合機能のプログラム指定フィールドにより、各支店が独自のマーケティングインフラを必要とせずに、支店主導のカレンダー作成が可能になります。開発部門はボトルネックではなく、オーケストレーターとしての役割を果たします。

建築業者の持ち帰り

  • 単一選択ではなく、複数選択として指定する。 実際の寄付者は複数のプログラムに寄付をします。それを単一の選択肢としてモデル化すると、不都合な妥協を強いられることになります。
  • 1通のダイナミックメールは、6通のセグメント化されたメールよりも効果的です。 6つの並行したニュースレターは、6つの承認サイクル、6つのレイアウト、そして6つのミスを犯す機会を意味します。条件付きブロックは拡張可能です。
  • 印刷物が発送されている間は、デジタル印刷を抑制してください。 複数のチャネル間での連携は、思慮深い作業と疲弊する作業の分かれ目となる。
