出席とキャンセルの同期：Klaviyoでのスイミングスクール再登録の保存

季節限定プログラムが再登録時に苦戦する理由

水泳教室、子供向け武道教室、音楽教室など、季節ごとに開催されるプログラムはどれも同じような仕組みになっています。8週間から12週間のセッションがあり、終了時には厳しい再登録の締め切りが設けられ、保護者は他の習い事やパートタイムの仕事と両立しながら、子供を預けることになります。締め切り前の2週間以内に保護者の注意を引けなければ、その枠はウェイティングリストの家族に譲られ、お子さんは次のセッションには参加できません。

仮に、タイドプール・スイム・アカデミー（例示）は、屋内プール1つで季節ごとのセッションを運営する、生徒数620人のスイミングスクールだとします。実際の再登録プロセスは問題ありません。問題は上流にあります。勢いを失った保護者（2回連続のキャンセル、休暇、病欠など）は、どこにもフラグが立てられていません。Klaviyoは、登録開始の1週間前に、全員に同じ定型的な再登録の案内を一斉送信します。退会リスクが最も高い子どもたちは、個別の救済措置を受けることができません。

Mindbodyが示す情報とKlaviyoが実行できること

Mindbodyはここで重要なことをすべて把握しています。すべてのクラスには出席者リストがあり、すべてのキャンセルにはタイムスタンプが付けられ、すべての登録には開始日と終了日があります。問題は、これらの情報がKlaviyoに反映されないことです。受付担当者は金曜日に「3回以上の欠席」レポートを作成し、月曜日にマーケティング担当者に渡します。マーケティング担当者は水曜日までにKlaviyoの単発セグメントを作成します。その頃には、キャンセル受付期間はすでに終了しています。

市販の連携ツール（Zapier、Makeなど）は、単一の出席イベントを処理することはできる場合もありますが、データ量が多い場合（週14回のクラスがあるスイミングスクールでは、1回のセッションで数千件の出席記録が生成されます）、処理が追いつかず、独自のロジックレイヤーなしでは、欠席と正当な理由による欠席を区別することもできません。

APIANTアプローチ

CRMConnect MindbodyとKlaviyoは、勤怠とキャンセルを第一級の同期イベントとして扱います。APIアプリの3つの要素がこれを実現します。

  • クラス同期と出席トラッキング Klaviyoは、今後の予約状況、出席状況、キャンセル状況に関する最新情報を常に把握します。
  • リアルタイムのクライアントプロフィール同期 保護者との連絡記録を、子供の在籍状況をプロフィール属性として整合させておく。
  • 来店追跡 欠席した授業のフローが誤って検出されないように、最近の訪問を毎日照合します。

Klaviyo側では、保護者のメールアドレスが固有の鍵となります。自分のメールアドレスを持たない子供たち（この年齢の子供たちのほとんどはそうですが）は保護者のプロフィールに紐づけられるため、実際にレッスンを予約する担当者（保護者）に情報が届くようになっています。

キャンセル・リカバリーフローの設計

まず最初に目指すべき流れは短く、崖ではなく、揺れを狙ったものである。

  1. トリガー： Mindbodyのキャンセルイベントは、24時間以内に開催予定だったクラスに限定されました。
  2. 4時間待ってください。 病気の親を不意打ちで襲うことを避ける。
  3. メール1：来週のご予約枠を確保いたしました。 Klaviyoのプロフィールから事前に入力された日付と時間を使用して、お子様の次回のレッスンの予定を再確認します。
  4. ブランチ mindbody_cancellations_last_30d:
  5. 2未満の場合：終了フロー。
  6. 2つ以上の場合：続行します。
  7. メール2（2日後）：お子様のコーチからのメッセージです。 補習授業の枠を提供します。これは、爆発では不可能な、目標を絞ったセーブ試行です。

この方法が便利なのは、分岐処理があるからです。1回のキャンセルはノイズに過ぎません。1ヶ月に3回キャンセルされた場合は、何らかの兆候であり、保存処理はその兆候を反映させるべきです。

再登録期間フローの設計

2つ目の流れはセッションごとに1回実行され、境界線上の子供を持つ親に対してのみ適用されます。

  1. トリガー： 日付ベースで、再登録開始日の14日前まで。
  2. 観客： プロファイル mindbody_active_enrollment それは本当です。
  3. ブランチ mindbody_attendance_rate_session:
  4. 80%以上：標準的な「席を確保してください」メール。
  5. 50～80パーセントの場合：「授業を欠席している生徒が何人かいることに気づきました」というメールに、コーチからのメモと確認アンケートを添付します。
  6. 50%未満の場合：メールはスキップし、ヘッドコーチに転送して手動で電話をかける。（Klaviyoプロファイルはフロントデスクダッシュボード用にタグ付けされています。）
  7. 7日間待ってから、再登録したユーザーのプロフィールを非表示にします。
  8. 締め切り48時間前、最終リマインダー まだ更新されていないセグメントについて。

「メールをスキップしてコーチに転送する」という部分は、ほとんどの自動化ツールがスキップしてしまう部分です。出席率の低い家庭には、メールではなく、人間による対応が必要です。Klaviyoは電話をかける必要はなく、適切な担当者を特定すれば良いのです。

Klaviyo profile attributes for swim school re-enrollment:
- mindbody_active_enrollment: true|false
- mindbody_cancellations_last_30d: int
- mindbody_attendance_rate_session: 0-100
- mindbody_next_class_at: ISO timestamp
- mindbody_kid_name: string (custom attribute on parent profile)

あくまでも参考例であり、実際の顧客像ではありません。

  • 資金流入前の再登録率（基準値）：約65～70％。
  • 出席状況に応じた配信による再登録率：75～82％の範囲に上昇。これは主に、以前は一般的な一斉配信を受けていた出席率50～80％の層からの上昇によるもの。
  • 受付業務でリスト作成に費やした時間：1セッションあたり約6～8時間。これは完全に元の時間に戻せる。
  • 「うちの子が先週学校を休んだ後、誰かフォローアップしてくれましたか？」という保護者からの苦情は激減した。なぜなら、誰かがフォローアップしてくれたからだ。

実際の効果は、ベースライン、価格設定、そしてヘッドコーチが実際に手動で指示を出しているかどうかによって決まります。統合機能は、適切なリストを提供するだけです。

ビルダーテイクアウト

  • キャンセルと出席は、レポートのエクスポートではなく、Klaviyoのイベントとして扱ってください。レイテンシーの違いが、ゲームのすべてを左右します。
  • 入学したかどうかだけでなく、出席率に基づいて支店を開設する。健全、不安定、解散の3つの区分には、それぞれ異なる対応が必要だ。
  • 出席率が最も低い層にのみ人的アプローチを行い、残りはKlaviyoに任せましょう。ツールは誰に電話をかけるべきかを教えてくれるべきであり、一連の操作で電話を代替できるかのように見せかけるべきではありません。
