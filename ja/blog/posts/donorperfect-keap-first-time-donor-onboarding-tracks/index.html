DonorPerfectコードを活用し、Keapの別々のトラックで新規寄付者と企業スポンサーをオンボーディングします。

Fred Lumiere 2025年6月2日 6分で読めます
#非営利団体#ドナーパーフェクト#キープ#CRMConnect

25ドルの初回寄付者と25,000ドルの企業スポンサーに同じウェルカムメールを送るべきではない。しかし、DonorPerfectとKeapを併用しているほとんどの地域医療資金調達機関では、まさにそのような事態が起きている。両システムは寄付者の種類を共有しないため、すべての新規連絡先がKeapに区別なく登録されてしまう。その結果、寄付者への対応がおろそかになり、寄付者の定着率が低下し、企業スポンサーはいつまで経っても届かない感謝のメールをひっそりと待つことになる。

これは、CRMの問題を装ったセグメンテーションの問題です。ウェルカムエクスペリエンスを分岐させるために必要なデータはDonorPerfect（寄付者タイプ、勧誘コード、寄付指定、マッチングギフトフラグ）に格納されています。Keapにはこのデータを読み取る方法がないため、ルーティングを行うことができません。手動でタグ付けする方法は最初の1か月は機能しますが、2か月目以降は機能しなくなります。

市販のツールが失敗する理由

一般的なiPaaSコネクタは、DonorPerfectを単なる連絡先リストとして扱います。名前、メールアドレス、場合によっては寄付金額を同期しますが、DonorPerfectの寄付者タイプコードが、その後のあらゆるプロセス（寄付の呼びかけ、寄付者との関係構築、理事会への報告など）におけるセグメンテーションの鍵となることを理解していません。このコードデータがなければ、Keapは機能せず、「オンボーディングの自動化」は誰にも当てはまらない、画一的なシーケンスになってしまいます。

もう一つの失敗例は、深夜にまとめて一方的に寄付を募ることです。月曜日の朝に寄付を約束した企業スポンサーは、感謝の連絡を受けるまで36時間も待たされることになります。これはスポンサーシップではなく、単なる事務処理上の負担です。2万5000ドルの寄付を検討しているスポンサーにとって、寄付から最初の感謝の連絡までの時間は、最も強力なエンゲージメントシグナルの一つです。安易なコネクターは、このシグナルを誰にも無料で提供してしまうことになります。

3つ目の落とし穴は、ドロップダウンリストのずれです。DonorPerfectでは、寄付者タイプ、募金コード、指定項目、その他多数の項目にドロップダウンリストを使用しています。開発担当者がDonorPerfectで新しい企業ティアの値を追加しても、汎用コネクタがそれをKeapに反映しません。3か月後、Keapには古いドロップダウンリストの値が残り、自動化処理が正しく機能せず、誰かが金曜日に手作業で修正作業を行うことになります。そして、このサイクルが繰り返されます。

APIANTアプローチ

DonorPerfectとKeap向けのCRMConnectは、まさにこの目的のために設計されています。オンボーディングにおいて重要な3つの要素は以下のとおりです。

  • CodeSync DonorPerfectのドロップダウンリスト（寄付者タイプ、勧誘コード、寄付指定、ソース）を、対応するドロップダウン値を持つKeapのネイティブカスタムフィールドとして反映します。カテゴリは自動的に整列されるため、誰も並行リストを管理する必要はありません。
  • タグとしてのフラグ DonorPerfectの寄付者フラグをKeapタグに変換するため、「マッチングギフト対象」、「企業スポンサー」、「役員候補者」などの属性がKeapにおける主要なセグメンテーションとして利用できるようになります。
  • リアルタイムギフト同期 DonorPerfectが寄付データ（金額、日付、用途、アピールポイント、キャンペーン）を記録するとすぐに、Keapにデータを送信します。トリガーは「初回寄付日」です。

具体的なステップ

ウェストサイド・コミュニティ・ヘルス・アライアンスという架空のFQHC（連邦政府認定地域保健センター）の資金調達部門（個人寄付者3,400名、企業スポンサー60社）を例にとると、オンボーディングの分岐は次のようになります。

  1. コードをマッピングする。 CRMConnect の CodeSync インターフェースで DonorPerfect の Donor Type Keapカスタムドロップダウンへのフィールド。値の例： Individual, Corporate, Foundation、および Memorial 自由記述テキストではなく、ネイティブのドロップダウンオプションとして表示される。
  2. 同期するフィールドを選択してください。 初回寄付日、最終寄付日、総寄付額、最大寄付額、寄付者タイプ、アピールコード、および開発チームが使用するマッチングギフトフラグの同期を有効にします。
  3. Keapキャンペーンを2つ作成します。 個人向けオンボーディングでは、21日間で5回の連絡を行います。税控除証明書付きのお礼状、創設者からのメッセージ、活動成果の紹介、ボランティアへの招待、2回目の寄付のお願い（ソフトなアプローチ）です。企業向けスチュワードシップでは、14日間で3回の連絡を行います。ロゴ掲載オプション付きの正式な謝意表明、担当開発責任者の紹介、対面での面談依頼です。
  4. 最初のギフトの日付同期時にトリガーします。 Keapでは、キャンペーンの目標は「初回寄付日が入力された状態で連絡先が作成された」ことです。寄付者タイプによって適切な順序にルーティングされます。
  5. 企業スポンサーを自動的に割り当てます。 いつ Donor Type = CorporateKeapは、企業寄付担当者に48時間以内の期限を設定したタスクを作成します。トリアージ待ちの間に見込み客が不発に終わることはもうありません。
  6. マッチングギフトの対象となる寄付者をタグ付けしてください。 Flags-as-Tags は、 matching-gift Keapにタグを付けることで、個々のトラックに「雇用主がこの寄付に同額を拠出する場合があります」というブロックが動的に挿入されます。
  7. 追悼や記念の贈り物を禁止する。 別のフィルタ経路 Donor Type = Memorial そして Tribute 営業的な歓迎シリーズではなく、繊細な対応を重視するトラックに記録を振り分ける。

結果

このパターンを導入した後の、同規模の中規模医療システム財団における代表的な数値：

  • 初めて個人寄付を行った人の12か月間の継続率は、およそ23％から38％に上昇する（業界全体の初回継続率のベンチマークは20％台前半である）。
  • 企業からの寄付の発送から最初のフォローアップまでの時間が、36時間から10分未満に短縮されます。
  • 開発担当者の順番待ちリストの整理は、月曜の朝の恒例行事から、リアルタイムのKeapタスクリストへと縮小した。
  • マッチングギフトの利用率は、年末の呼びかけではなく、ウェルカムメールで最初にそのオプションを提示した場合、ほぼ2倍になる。
  • 以前は月曜日に新規寄付記録を手作業で分類していた開発担当者は、週におよそ6時間分の時間を確保できるようになり、その時間を中堅寄付者への感謝の電話に再投資している。

過大な期待は禁物です。コンテンツが弱ければ、これらの施策はどれも定着率の向上には繋がりません。統合によって、一般的なウェルカムメッセージを送信する運用上の理由はなくなりますが、メッセージングは依然として2回目の寄付につながるものでなければなりません。CRMConnectを導入しても、ウェルカムコンテンツが既に強力で、ボトルネックが別のところ（年間募金の規模、理事会の関与、年末の募金カレンダーなど）にあったため、定着率の向上はわずかだった財団もあります。一方、何年も差別化されていないウェルカムメッセージを送信していたため、セグメンテーションが長年の課題だった財団は、大きな成果を上げています。統合によって最高の効果が得られると考える前に、既存のオンボーディングプロセスを監査してください。

一つ注意すべき点があります。38%という保持率は、寄付者の種類によってコンテンツが実際に意味のある形で変更されることを前提としています。企業向けと個人向けのシーケンスが件名だけ異なる場合、保持率は低下します。コンテンツの差別化は、技術的な設定と並行して計画し、後続のプロジェクトとして行うべきではありません。

注目すべき点

運用開始前に考慮すべき事項がいくつかあります。ウェルカムシリーズを有効にする前に、サンプルとなる追悼寄付に対して抑制ロジックをテストしてください。追悼寄付者への営業的なウェルカムメールが誤って送信されてしまうと、1年間かけて築き上げてきた関係が台無しになってしまいます。企業スポンサーが同じドメインに複数の連絡先を持っている場合、Keapの重複検出機能が期待どおりに動作することを確認してください。寄付者が実際に行動を起こせるように、財団が使用するマッチングギフトデータベース（HEPdata、Double the Donationなど）がタグだけでなくメール本文にも参照されていることを確認してください。

企業トラックのエッジケースを計画する。新しい企業スポンサーの最初の寄付は、予期しない経路（CEOからの個人的なカード、経理部からの小切手など）で届くことがあり、 Corporate 自動的に。最近の初回寄付に関する週次レビューを作成し、誤ったシーケンスが実行される前に、誤ってコード化されたレコードを検出します。

建築業者の持ち帰り

  • ドナーの種類がセグメンテーションの鍵となります。 CodeSyncを使って、自由形式のテキストではなく、実際のドロップダウンリストとして同期してください。自由形式のテキストは1ヶ月以内に劣化してしまいます。
  • 記録作成ではなく、最初の贈り物の日付がトリガーとなります。 何年もギフトが贈られていない見込み客の記録は、最終的にギフトが贈られた日に、まるで新規の見込み客であるかのようにウェルカムシリーズに組み込むべきではない。
  • 追悼や企業関連の楽曲は、最初から専用のトラックを用意する必要がある。 後からそれらを改修するということは、キャンペーンのすべてのシーケンスを書き直すことを意味する。
